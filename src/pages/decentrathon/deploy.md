Для человека с чистой виртуальной машиной Ubuntu. Образ не содержит данных кейса и ключей: артефакты, файл
правил и база монтируются при запуске. Ничего из этого не коммитится и не кладётся в образ.

**Ключ модели не нужен.** Без `GEMINI_API_KEY` (и при `LLM_BACKEND=none`) сервис работает полностью офлайн: категорию даёт
классификатор из образа (`models/classifier.npz`, только числа), пункт выбирает код, ответы идут по шаблонам и базе
знаний, цена $0, сеть не используется. Именно так работает `make predict` у жюри. Рекомендуемый режим публичного сайта
тоже `LLM_BACKEND=none` (обоснование и числа: `docs/report.md`, раздел 6.5), чтобы сайт показывал то же поведение,
что и `make predict`. Gemini включается ключом и `LLM_BACKEND=gemini`; режим виден в `/health` (`llm_backend`).

**Настоящие тикеты на публичном инстансе есть только в одном месте: в разметке («Разметка»), только за входом `dev`.**
Очередь наполняется только 35 выдуманными обращениями из `api/demo_tickets.json`, проверка языка работает только на
выдуманных. Жюри настоящих текстов не получает, ответы с настоящим текстом уходят с `Cache-Control: no-store`,
текст не попадает в логи, телеметрию, образ, git и демо-сборку. Файл `gold_todo.csv` лежит на хосте в `./private`,
монтируется только для чтения и читается при старте (раздел 13). Остальные настоящие тикеты обрабатываются только локально
(`make predict` или контейнер жюри), офлайн без ключа либо с платным ключом, но не через бесплатный тариф.

## 1. Машина

- Минимум: 2 vCPU, 4 ГБ ОЗУ, 20 ГБ диска, GPU не нужен. Ubuntu 22.04 или 24.04.
- Публичный IPv4 (или IPv6) и доменное имя.
- Один воркер `uvicorn`: пределы запросов и входов живут в памяти процесса. Масштабировать репликами нельзя.

## 2. Порты и DNS

- Файрвол (cloud security group и/или `ufw`): входящие **22** (SSH, лучше только с вашего адреса), **80** и
  **443/tcp** (+ **443/udp** для HTTP/3). Порт 8000 наружу не открывать: приложение слушает только внутри сети
  compose, к нему ходит Caddy.
- DNS: A-запись (и AAAA, если есть IPv6) домена из `DOMAIN` на адрес машины. Сертификат Caddy получает сам
  (Let's Encrypt), для этого порты 80 и 443 должны быть доступны из интернета, а запись DNS уже указывать на
  машину. Пока запись не распространилась, Caddy будет повторять попытки и писать ошибку в лог.

```
sudo ufw allow OpenSSH && sudo ufw allow 80/tcp && sudo ufw allow 443 && sudo ufw enable
```

Примечание: порты, опубликованные Docker, обходят `ufw`. Поэтому в compose опубликованы только 80 и 443; у
приложения публикации нет.

## 5. Приватные файлы

Артефакты и правила передаются **приватно** (scp, зашифрованный носитель), не через git, чат или публичные
хранилища.

На машине, где артефакты собраны (`make build` уже выполнен):

```
make bundle                        # создаёт artifacts-runtime.tgz (конфиденциально)
scp artifacts-runtime.tgz user@host:~/
```

В архив входят артефакты сервиса и копии `rules.json` и `taxonomy.json` из `HANDOUT_DIR` (если файлы там
есть). Сервис ищет эти два файла сначала в `HANDOUT_DIR`, затем в папке артефактов, поэтому одного архива
достаточно. **Образ и архив должны быть собраны из одного коммита**: индекс базы знаний (`kb_index.joblib`) читается только той
же версией scikit-learn, numpy, scipy и joblib, что его записала (классификатор в образе это `.npz` из чисел и от версий не зависит); версии закреплены в `pyproject.toml`.
После обновления зависимостей пересоберите артефакты (`make build`) и архив.

На сервере:

```
mkdir -p artifacts-runtime
tar -xzf ~/artifacts-runtime.tgz -C artifacts-runtime
chmod -R go-rwx artifacts-runtime && rm ~/artifacts-runtime.tgz
ls artifacts-runtime               # category_rules.json exemplars.json kb.json kb_index.joblib uz_vocab.json rules.json taxonomy.json [eval_report.json]
```

Отдельно `rules.json` передавать не нужно. Если всё же хотите держать его вне архива, положите файл в папку
на хосте и укажите её в `HANDOUT_DIR` (он подмонтируется только для чтения и будет главнее копии в архиве).
Если по этому пути файла нет, Docker создаст на его месте пустой каталог: это не страшно, сервис возьмёт копию
из `artifacts-runtime/`. Без артефактов сервис всё равно стартует
и отвечает офлайн (модель классификатора лежит в образе); нет только базы знаний, образцов и словаря узбекского.

## 6. deploy.env

```
cp deploy.env.example deploy.env && chmod 600 deploy.env
openssl rand -hex 32               # значение для SESSION_SECRET
nano deploy.env
```

| Переменная | Что это |
|---|---|
| `GEMINI_API_KEY`, `OPENAI_API_KEY` | платные ключи моделей, необязательны. Нет ключа: офлайн-режим (`LLM_BACKEND=none`), качество описано в `docs/report.md`, раздел 6.5 |
| `LLM_BACKEND` | `auto` (по умолчанию: Gemini при ключе, иначе офлайн), `none` или `gemini` |
| `PUBLIC_MODE` | `1` на публичном инстансе |
| `SESSION_SECRET` | длинная случайная строка. Без неё сервис в `PUBLIC_MODE` не стартует |
| `JURY_OPEN` | по умолчанию `1` (строки в `deploy.env` может не быть): жюри входит без пароля, одной кнопкой «Войти», и не получает данных кейса (см. раздел 13). `0` возвращает вход жюри по паролю |
| `JURY_LOGIN`, `JURY_PASSWORD` | вход для жюри. `JURY_PASSWORD` нужен только при `JURY_OPEN=0`: в `PUBLIC_MODE` с `JURY_OPEN=0` без него сервис не стартует, при открытом жюри стартует и без него |
| `DEV_LOGIN` (по умолчанию `dev`), `DEV_PASSWORD` | вход для команды: разметка, проверка языка, панель результатов. Пустой пароль: роль выключена |
| `GOLD_FILE` | путь к `gold_todo.csv` внутри контейнера, оставьте `/srv/private/gold_todo.csv` |
| `API_KEY` | необязательно: заголовок `X-API-Key` для `POST /triage` из скриптов |
| `DAILY_LLM_USD` | потолок трат на модель за 24 часа, например `3` |
| `DOMAIN` | домен, например `copilot.example.org` |
| `HANDOUT_DIR` | папка на **хосте** с `rules.json`, например `./private`; можно оставить пустой путь, если `rules.json` лежит в архиве артефактов. В контейнер монтируется только этот файл |

`deploy.env` в git не попадает (`.gitignore`). Не вставляйте его содержимое в чат и тикеты.

## 7. Запуск

Все команды публичного инстанса берут переменные из `deploy.env`:

```
docker compose --env-file deploy.env build
docker compose --env-file deploy.env up -d
```

Ключ `--env-file` обязателен: из него берутся `DOMAIN` и `HANDOUT_DIR` для подстановки в compose; без `DOMAIN`
compose сразу завершается ошибкой, а без `--env-file` прочитал бы `.env` из папки (ключи разработчика). Чтобы не
печатать его каждый раз: `export COMPOSE_ENV_FILES=deploy.env`.

## 8. Проверка

```
docker compose --env-file deploy.env ps          # app: healthy, caddy: running
docker compose --env-file deploy.env logs caddy | tail   # "certificate obtained"
curl -s https://$DOMAIN/health                                    # {"status":"ok"}
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://$DOMAIN/triage \
  -H 'content-type: application/json' -d '{"kind":"report","messages":[{"role":"player","text":"тест"}]}'   # 401
```

Затем открыть `https://<DOMAIN>/` и войти. Очередь заполнится 35 выдуманными обращениями при первом старте
(идёт в фоне, в ответе очереди `seeding: true`); при перезапуске заново не наполняется.

## 9. Обновление

```
git pull
docker compose --env-file deploy.env build
docker compose --env-file deploy.env up -d     # пересоздаст app, база сохранится
```

Новые артефакты: распаковать в `artifacts-runtime/` и `docker compose ... restart app` (артефакты читаются
при старте процесса).

## 10. Резервная копия базы

База (очередь, правки админов, телеметрия, отозванные сессии) лежит в именованном томе `appdata`
(`/data/copilot.sqlite`). Копия без остановки:

```
docker compose --env-file deploy.env exec app python -c \
  "import sqlite3; s=sqlite3.connect('/data/copilot.sqlite'); d=sqlite3.connect('/data/backup.sqlite'); s.backup(d); d.close()"
docker compose --env-file deploy.env cp app:/data/backup.sqlite ./copilot-$(date +%F).sqlite
docker compose --env-file deploy.env exec app rm /data/backup.sqlite
```

Копия содержит тексты обращений: хранить как конфиденциальную, не коммитить (`*.sqlite` в `.gitignore`).
Если удалить базу, потеряется и история трат, по которой считается дневной потолок.

## 11. Смена пароля

Поменять `DEV_PASSWORD` (или `JURY_PASSWORD` при `JURY_OPEN=0`; при необходимости и `SESSION_SECRET`) в `deploy.env`, затем:

```
docker compose --env-file deploy.env up -d --force-recreate app
```

Смена пароля обрывает открытые сессии этой роли; переключение `JURY_OPEN` обрывает сессии жюри. Каждое изменение `deploy.env` требует пересоздания контейнера:
простой `restart` переменные не перечитывает.

## 13. Роли, разметка и проверка языка

Две роли: `dev` (команда, свой пароль `DEV_PASSWORD`, имя вводят при входе) и `jury` (жюри, без пароля, пока не задан `JURY_OPEN=0`).
Роли «тестер» (`guest`) больше нет: проверку языка проходит `dev`, на всех трёх языках; голоса тестеров остались в базе и в выгрузках,
старые сессии тестера не действуют, человек попадает на форму входа. Роль `dev` без пароля выключена, `PUBLIC_MODE` не требует пароля разработчика.

**Открытое жюри и данные кейса.** Правила кейса запрещают публиковать данные кейса и производные образцы, а по ссылке теперь входит любой.
Поэтому открытая сессия жюри получает ссылки на пункты (`ОП 2.1`), но не текст правил (`GET /api/rules/...` отвечает 403), не санкции из правил,
не ответы из базы знаний и не образцы ответов админов. На инстансе с `PUBLIC_MODE=1` и открытым жюри база знаний и образцы не строятся (вопрос уходит
админу, как в `make predict` без базы знаний); ничего на сервере менять не нужно, файлы `kb.json` и `exemplars.json` просто не используются.
Команда (`dev`) видит текст правил. На таком инстансе режим черновика всегда `neutral`, что бы ни стояло в `DRAFT_MODE`.

**Старые обращения очереди.** Очередь была засеяна с моделью, и в её черновиках бывает текст правил. При старте на инстансе с `PUBLIC_MODE=1` и открытым жюри
все `seed`-обращения один раз переписываются офлайн-конвейером, без вызова модели (`api/rewrite.py`); id, время и текст обращений остаются, голоса, разметка и элементы проверки языка
не затрагиваются. Метка выполнения лежит в таблице `migrations`; повторный старт ничего не пишет. Автодеплой делает копию базы перед обновлением (`pre-…sqlite`), при откате она
возвращается, и старые строки возвращаются вместе со старым кодом. С `JURY_OPEN=0` и без `PUBLIC_MODE` строки не меняются.

**Разметка настоящих тикетов (роль `dev`).**
1. На сервере положить файл в `./private/gold_todo.csv` рядом с `docker-compose.yml` (там уже лежит `rules.json`):
   `scp gold_todo.csv user@host:~/copilot/private/`. Папка в `.gitignore` и `.dockerignore`, в контейнер монтируется
   `./private:/srv/private:ro`, образ файла не содержит.
2. Пересоздать контейнер (`docker compose --env-file deploy.env up -d --force-recreate app`): файл читается при старте
   и добавляет в базу только новые строки, метки не трогаются. Без пересоздания: кнопка «Проверить ещё раз» на экране
   «Разметка» (`POST /api/labels/reload`).
3. Двое входят под ролью `dev` со своими именами. Первые 30 строк (`first_30_shared=1`) размечают оба независимо, ответ второго не
   показывается; остальные строки достаются тому, кто первым дошёл. Метки и имена лежат в базе на томе `appdata`.
4. Выгрузка: «Прогресс и результаты» → «Скачать gold CSV» (основной лист в формате `gold_todo.csv`) и «Лист: <имя>»
   (второй лист для `--gold2`). Сохранить как `artifacts/gold_todo.csv`, запустить `make eval`.

**Удаление настоящих тикетов: в течение 14 дней после объявления победителей.** Как:
1. `rm ./private/gold_todo.csv` на хосте (файл `rules.json` в той же папке оставьте или удалите по общему правилу удаления).
2. Остановить сервис: `docker compose --env-file deploy.env stop app`.
3. Скачать нужное заранее (gold CSV, оценки языка), затем убрать тексты из базы. Если база больше ничего не хранит, проще
   удалить том целиком: `docker compose --env-file deploy.env down -v` (уходят очередь, история трат и отзывы проверяющих).
   Если том нужен, очистить только таблицы разметки:
   `sqlite3 /var/lib/docker/volumes/support-copilot_appdata/_data/copilot.sqlite "DELETE FROM gold_labels; DELETE FROM gold_items; VACUUM;"`
4. Скачанные CSV на ноутбуках и в `artifacts/` удалить вручную.

**Проверка языка (роль `dev`).** Только выдуманные обращения из `api/review_items.json` (в образе, без модели).
Элементы добавляются при старте по `id`; изменённый текст ответа с тем же `id` становится новой версией и просит новой
проверки, старые оценки остаются в выгрузке. Обновить после смены ответов сервиса:
`python -m cli.build_review items` (без генерации обращений; `--offline` без вызовов модели), закоммитить файл и пересобрать образ.
Новые выдуманные обращения: `python -m cli.build_review tickets` (платный шаг, несколько центов). Оценки: «Прогресс и результаты» →
«Скачать оценки CSV» и «Скачать исправления CSV».

## 12. Остановка и расходы

```
docker compose --env-file deploy.env down        # остановить, тома сохраняются
docker compose --env-file deploy.env down -v     # и удалить тома (база, сертификаты)
```

Остановка контейнеров не останавливает оплату машины: чтобы не платить за вычисления, остановите или удалите
саму машину у провайдера (диск и статический IP тоже тарифицируются). Расход на модели ограничен
`DAILY_LLM_USD`; чтобы выключить его совсем, уберите ключи из `deploy.env` и пересоздайте `app`.
Пока запущен Caddy, том `caddy_data` хранит сертификат: при `down -v` лимиты Let's Encrypt на выпуск
сертификатов могут сработать при частых пересозданиях.

Логи контейнеров ротируются (json-file, 3 файла по 10 МБ на сервис), диск они не заполнят. В журнале Caddy
нет ключей и cookie: заголовки `X-Api-Key`, `Authorization`, `Cookie`, `Set-Cookie` вырезаются фильтром в
`Caddyfile`.

## Локальный запуск для жюри

Без Caddy, без `PUBLIC_MODE`, порт 8000, `POST /triage` по контракту кейса без учётных данных.

Флаг `-f docker-compose.local.yml` обязателен: без него compose берёт публичный `docker-compose.yml`, который
требует `DOMAIN` и завершается ошибкой.

```
docker compose -f docker-compose.local.yml build
mkdir -p artifacts-runtime && tar -xzf artifacts-runtime.tgz -C artifacts-runtime   # если архив передали
GEMINI_API_KEY=<ключ> docker compose -f docker-compose.local.yml up   # без ключа и без артефактов тоже работает
curl -s -X POST localhost:8000/triage -H 'content-type: application/json' \
  -d '{"kind":"report","messages":[{"role":"player","text":"не пришли донат-монеты"}]}'
```

**Внимание:** Docker Compose сам читает файл `.env` рядом с compose-файлом, если он есть, и подставляет из него
`GEMINI_API_KEY` и остальное: у жюри такого файла нет, у разработчика он может быть (платный ключ уйдёт в
контейнер). Чтобы использовать только окружение оболочки:
`docker compose --env-file /dev/null -f docker-compose.local.yml up`.
Правила и таксономия берутся из `artifacts-runtime/` (`rules.json`, `taxonomy.json` лежат в архиве). Без `artifacts-runtime/` сервис работает офлайн на модели из образа (без базы знаний и без пунктов правил, если нет `rules.json`). Ключ можно передать только через
окружение оболочки: в образ и в compose он не записывается. Чтобы включить вход в интерфейс, добавьте
`JURY_PASSWORD` и `SESSION_SECRET` в окружение запуска.

### `make predict` в контейнере

Читает и пишет смонтированную папку (на хосте), без Python на хосте:

```
mkdir -p io && cp tickets.jsonl io/
make predict-docker DIR=./io IN=tickets.jsonl OUT=pred.jsonl
```

Эквивалент командой compose:

```
docker compose -f docker-compose.local.yml run --rm --no-deps --user "$(id -u):$(id -g)" \
  -v "$PWD/io:/io" local python -m cli.predict --in /io/tickets.jsonl --out /io/pred.jsonl
```

Результат: `io/pred.jsonl` и `io/pred.jsonl.telemetry.jsonl`. Артефакты берутся из `./artifacts-runtime`,
если папка непустая. `--user` нужен, чтобы файлы на хосте принадлежали вам, а не uid 10001.

## Автодеплой на домашний сервер (pull-based CD)

Для сервера `ja-server` (Docker Compose за туннелем Cloudflare, без Caddy). GitHub Actions в этом репозитории не
запускаются, а раннер зарегистрировать нельзя, поэтому сервер сам раз в 2 минуты забирает ветку. Подробности и
проверка: `docs/stages/16-autodeploy.md`.

**Как это работает.** Пользовательский таймер systemd `support-copilot-deploy.timer` запускает
`~/apps/bin/autodeploy.sh` (установленная копия, не файл из рабочего дерева, поэтому пушем его не подменить).
Скрипт: `git fetch`; нет нового коммита на `DEPLOY_BRANCH` (по умолчанию `ja-track-3`): ничего не делает. Есть:
только fast-forward (разошлась история: стоп и статус `diverged`, force не бывает). Затем сборка и тесты в цели
`test` из `Dockerfile` (контейнер без сети, без данных и ключей; фронтенд собирается там же); тесты упали: старая
версия работает, коммит помечается как проваленный и не повторяется. Тесты прошли: образ текущей версии
получает тег `previous`, поднимается только сервис `app`, ждёт `/health` на `127.0.0.1:8000`, затем внутри
контейнера проверяет, что правила загружены и модель классификатора доступна. Любой сбой: возврат на прежний образ
и прежний коммит, проверка здоровья, статус `rolled_back`. Тома не удаляются, `deploy.env`, `artifacts-runtime`,
`private`, `cloudflared` и другие сервисы не затрагиваются.

**Установка** (один раз и при обновлении самого скрипта; без sudo): `make install-autodeploy` с Мака
(= `bash deploy/install-autodeploy.sh`). Повторный запуск безопасен.

**Статус.** `make deploy-status` (только чтение по ssh): `~/apps/deploy-status.json` (коммит, состояние, время,
класс последней ошибки, число тестов) и последние строки `~/apps/deploy.log` (ротация по размеру, без секретов).
Состояния: `deployed`, `testing`, `deploying`, `tests_failed`, `build_failed`, `rolled_back`, `rollback_failed`,
`diverged`, `blocked_compose_change`, `paused`, `fetch_failed`. Подробный вывод последних тестов и сборки:
`~/apps/deploy-last-gate.log`, `~/apps/deploy-last-build.log`.

**Пауза.** `ssh homeserver 'touch ~/apps/deploy-paused'`; возобновить: `rm ~/apps/deploy-paused`.
Полностью выключить: `systemctl --user disable --now support-copilot-deploy.timer`.

**Откат вручную.** Автоматически откат делается при сбое выкладки. Вручную: поставить на паузу, затем
`cd ~/apps/support-copilot && git reset --hard <коммит> && docker tag support-copilot:previous support-copilot:latest
&& docker compose --env-file deploy.env -f docker-compose.yml -f docker-compose.ja.yml up -d --no-build --force-recreate app`.
Если на `ja-track-3` лежит плохой коммит, который прошёл тесты, надо запушить в ветку исправление или `git revert`:
сервер выложит его сам.

**Изменение `docker-compose.yml`.** Сравнивается весь разрешённый конфиг (`docker compose config`, вместе с
локальной надстройкой): все сервисы и все секции верхнего уровня (тома с `driver_opts`, сети, `secrets`, `configs`).
Не считаются изменением только значения `environment` (имена переменных считаются), `command` и `labels`. Любое
другое отличие от эталона, записанного при установке, а также любое изменение `Dockerfile` или `Caddyfile`: деплой
отклоняется (`blocked_compose_change`). Прочитайте diff (`git diff HEAD origin/ja-track-3 -- docker-compose.yml
Dockerfile Caddyfile`) и разрешите, записав в файл отпечаток именно этой версии (не меньше 16 символов, их печатает
`~/apps/bin/autodeploy.sh --fingerprint origin/ja-track-3` и строка в `deploy.log`):
`ssh homeserver 'echo <отпечаток> > ~/apps/allow-compose-change'`. Пустой файл, sha коммита или чужой отпечаток
ничего не разрешают. Так работает скрипт из этого репозитория; на сервере он обновляется только `make install-autodeploy`,
до этого действует старая проверка (только compose, файл с началом sha коммита). Файл удаляется только после успешной выкладки, которую он разрешил, а новая контрольная
сумма становится эталоном; при сбое он остаётся (удалите вручную, если передумали). Установщик
(`make install-autodeploy`) сам принимает compose с `origin/ja-track-3` как эталон: вы запускаете его осознанно, diff
печатается.

**Повторить провалившийся коммит.** Коммит, провалившийся в тестах (обе попытки) или в сборке не из-за сети,
больше не берётся. После исправления окружения: `ssh homeserver 'touch ~/apps/retry-commit'` (файл снимает отметку
с последнего коммита ветки и удаляется). Сборка, упавшая на сетевой ошибке (pip, npm, реестр), повторяется сама до
3 раз с паузой 5 и 10 минут, потом коммит помечается проваленным.

**База данных.** Перед каждой заменой `app` SQLite копируется из тома (`sqlite3 backup` во временном контейнере без
сети под uid приложения) в `~/apps/backups/pre-*.sqlite` (папка 700, хранятся последние 5). При откате база
возвращается из этой копии, а то, что записала упавшая версия, остаётся в `~/apps/backups/failed-*.sqlite`
(последние 2); данные, записанные между копией и откатом, из основной базы теряются. Тома не удаляются. После
успешной выкладки кэш сборки BuildKit урезается до `BUILD_CACHE_KEEP` (10 ГБ; `docker builder prune --reserved-space`,
образы и тома не затрагиваются).

**Новые артефакты и `gold_todo.csv`** передаёт `make push-private` (`GOLD=/путь/gold_todo.csv` по желанию; при
расхождении коммитов с сервером останавливается, `--force` продолжает): сборка
архива, scp, права (файлы читаются всеми внутри монтирования, потому что контейнер работает под uid 10001, а
родительские папки `~/apps` и `~/apps/support-copilot` имеют права 750), перезапуск `app`.

**Риск.** Любой, у кого есть право записи в ветку `ja-track-3`, может выполнить код в контейнере `app` на сервере:
тесты и сборка запускаются из его коммита. Контейнер без привилегий, но с доступом к `artifacts-runtime`, правилам и
ключам из `deploy.env` (они передаются в окружение). Ограничьте право записи в ветку, включите защиту ветки и
ревью, а при подозрении поставьте паузу.
