  (правило среды: исполнитель не пишет файлы-отчёты). Текст готов и лежит в рабочей папке исполнителя, его нужно
  добавить в PR вручную одним коммитом (docs-only). README и этот файл на него ссылаются.
- Код не менялся. `Dockerfile`, compose и `docs/deploy.md` не тронуты (их ведёт PR #9).

**Решения и причины.**
- Все числа взяты из отчётов этапов или из `eval_report.json` и `eval_report_holdout.json`. Где они расходились,
  взят JSON: приоритет против серебра на valid 0,609 и macro-F1 0,4505 (в отчёте этапа 5 стояло 0,62 и 0,43), варианты
  таблицы приоритета 0,657 / 0,5477 и 0,748 / 0,5623.
- Таблицы метрик разделены на три: чистая выборка (300), in-sample valid (1000, код настраивался на ней) и
  серебро. Золота нет, раздел «Проверка на ручной разметке» оставлен пустым с инструкцией.
- Примеры в отчёте: 8 выдуманных тикетов с настоящим выводом сервиса. Фрагменты санкций из текста правил заменены
  меткой, чтобы текст правил не попал в репозиторий. Номера пунктов оставлены.
- Среди примеров показан промах: узбекский платёж не поймал флаг платежа (категория `report.help`, p2, человек нужен).
  Он описан в рисках.
- Проверка носителями uz и kk не проведена: лист из 42 пар фраз подготовлен, колонки проверки пусты.

**Как проверить.**
```
make install PY=<python>     # в чистом venv: rc=0
make serve PORT=8765 HOST=127.0.0.1   # /health ok; POST /triage из README возвращает complaint.insult, cited ["2.1"]
make predict IN=… OUT=…      # 2 тикета, 2 строки вывода; без IN и OUT печатает usage и код 2
make eval ARGS="--limit 5 --report … --summary … --preds …"   # 5 тикетов, отчёт в сторону от artifacts/
make test                    # 1325 passed, 2 skipped (с артефактами)
make ci PY=<python>          # результат в описании PR
```
Живые прогоны для примеров: 11 выдуманных тикетов, платный ключ из `.env`, около $0,01 в сумме.
