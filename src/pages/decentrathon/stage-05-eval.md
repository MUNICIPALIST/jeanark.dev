**Сделано.**
- `cli/eval.py` (`make eval`, аргументы через `ARGS="--limit 100 --seed 1"`): прогоняет `tickets_valid` через
  `cli.predict.run` (тот же код, что `make predict`; конвейер не переписан). Сообщения `admin` и поля исхода
  (`verdict`, `punishment`, `violation`) срезаются до конвейера; ответ админа остаётся только как источник
  пунктов, которые он назвал (`rules.extract_refs`). Метрики: точность и F1 по классам для категории и
  приоритета (серебро; золото из `gold_todo.csv`, когда колонки заполнены, сплиты `tune` и `final`
  раздельно, `final` только с `--final`), согласие двух разметчиков на `first_30_shared` (`--gold2`),
  recall@draft и несуществующие цитаты, доля `needs_human` и автоответов, нарушения «всегда человек»,
  коды отказов проверки, пути, задержка p50/p95/p99, средняя и максимальная цена, превышения $0,002 по
  тикету, разбивка по языку ответа, контрфактические варианты таблицы приоритета. Работает без серебра,
  золота и `rules.json`. `--limit`/`--seed` (по умолчанию все 1000), `--reuse` пересчитывает отчёт по
  `runs/eval_preds.jsonl` без вызовов модели. Выход: `ARTIFACTS_DIR/eval_report.json` (только числа),
  `runs/eval_summary.md`, `runs/eval_preds.jsonl` (с текстами, не коммитится).
- `cli/compare.py`: `models` (4 модели на 60 тикетах) и `modes` (3 режима на 30 жалобах), судья
  `gemini-3.8-flash`. **Судья это прокси, не администраторы**: метки черновиков перемешаны, модель и режим
  скрыты, рядом настоящий ответ админа; оценки 1-5 по четырём критериям. Счётчик расходов `runs/spend.json`.
  `override_settings` подменяет `Settings` во всех модулях на время прогона.
- `core/draft.py`: `model_default`/`model_minority` могут называть модель OpenAI (`gpt*` идёт в Responses
  API); запасная модель не вызывается, если совпадает с основной. Без этого модели `gpt-*` нельзя было
  сравнить на равных условиях.
- Потолок цены тикета в `core/draft.py` (`COST_CAP_USD` = $0,002): дубликат (hedging) и запасная модель
  запускаются, только если оплаченные сбои плюс оценка следующего вызова (вход по длине промпта, 200
  токенов выхода) укладываются в потолок. Прежний выброс $0,0023: неудачный вызов на 500 токенов плюс дубликат.
  Один вызов ограничен `MAX_OUTPUT_TOKENS` (flash-lite около $0,0016 в худшем случае), поэтому тикет, начавший
  второй вызов, не может превысить потолок; для моделей с размышлением (3.8-flash) hedging фактически
  выключен. Тесты в `tests/test_draft.py`. `make eval` по умолчанию гоняет 4 тикета одновременно (равно
  `HEDGE_MAX_INFLIGHT`), чтобы hedging вёл себя как в боевом режиме; `meta` хранит `concurrency`, коммит,
  `CLASSIFIER_TRUST_BY_LANG` и пороги.
- Правки конвейера по итогам цикла качества (отдельный раздел ниже), тесты `tests/test_eval.py` (33),
  дополнения в `test_pipeline.py`, `test_templates.py`, `test_guard.py`.

**Как проверить.**
```
export ARTIFACTS_DIR=… HANDOUT_DIR=…
make eval PY=…                       # полный прогон 1000 тикетов, около $0,47 и 3-4 минуты
make eval PY=… ARGS="--reuse"        # пересчёт отчёта без модели
python -m cli.compare models --n 60 [--relaxed]   # ~$0,25 вместе с судьёй
python -m cli.compare modes --n 30                # ~$0,09
python -m cli.eval --holdout 300     # чистая выборка из train, ~$0,14
make test                            # 1324 теста без данных и сети
```

этом на uz классификатор прав, а модель нет в 20 тикетах. Значит, на uz классификатор не слабее, чем на ru

## Сравнение моделей

60 тикетов, дошедших до модели (путь `llm` в базовом прогоне): ru 31, uz 22, kk 7 (в valid kk всего 7,
взяты все, остальное добрано случайными тикетами из ru и uz; 20 на язык недостижимо). Один и тот же
промпт, запасная модель отключена. Два режима: боевые таймауты (вызов 3,5 с, всего 4,5 с) и «свободный»
(10 с, без hedging). Цена `gpt-6.1-terra` в таблице цен не задана: использована цена по умолчанию
$0,75/$3,75 за млн токенов (предположение).

Боевые таймауты (ответила модель из 60): gemini-3.5-flash-lite 60 (p95 1,69 с, $0,00055 в среднем),
gemini-3.8-flash 45 (p95 3,51 с, $0,00131, макс. $0,00205), gpt-6-luna 22 (p95 3,51 с), gpt-6.1-terra 23.
Модели кроме flash-lite не укладываются в 3,5 с примерно в половине вызовов и уходят в запасной шаблон.

Свободный режим (качество без бюджета времени):

| модель | ответила | p50 / p95, мс | цена среднее / макс | согласие с серебром | recall | судья (1-5) |
|---|---|---|---|---|---|---|
| gemini-3.5-flash-lite | 60 | 1109 / 1604 | $0,00054 / $0,00074 | 0,80 | 0,54 | 3,77 |
| gemini-3.8-flash | 59 | 3007 / 4589 | $0,00111 / $0,00201 | 0,80 | 0,54 | 3,85 |
| gpt-6-luna | 60 | 3083 / 4249 | $0,00014 / $0,00017 | 0,83 | 0,54 | 3,81 |
| gpt-6.1-terra (цена предположена) | 60 | 3421 / 5208 | $0,00105 / $0,00126 | 0,83 | 0,54 | 3,84 |

Все: отказов проверки 0, слов-выдумок uz (`lang_uz_vocab`) 0 из 22. Разница судьи между моделями 0,1 из 5
на 60 тикетах (шум). Критерии (flash-lite / 3.8-flash / luna / terra): соответствие 3,30 / 3,42 / 3,33 /
3,45; тон 3,73 / 3,76 / 3,73 / 3,75; язык 4,58 / 4,69 / 4,72 / 4,65; без необоснованных утверждений 3,47 /
3,51 / 3,45 / 3,52.

Ограничения сравнения: всего 60 тикетов (разности судьи 0,1 из 5 это шум); судья `gemini-3.8-flash`
одновременно один из кандидатов, возможна самопредпочтительность; цена `gpt-6.1-terra` предположена; результат
при боевых таймаутах смешивает задержку и качество (модель, не успевшая за 3,5 с, получает шаблон), поэтому
рядом дан «свободный» режим. Это сравнение не заменяет золото.

**Решение: `model_default` и `model_minority` остаются `gemini-3.5-flash-lite`.** Взвешенная оценка
(судья 0,40, согласие с серебром 0,30, прохождение проверки 0,20, recall 0,10) считается только среди
моделей внутри лимитов (средняя цена ≤ $0,0015, макс. ≤ $0,002, p95 ≤ 4,5 с, ответ в ≥90% случаев).
При боевых таймаутах это одна модель. Свободный режим, где `gpt-6-luna` выходил бы первым по оценке
(0,83 против 0,80 по серебру на 60 тикетах, p50 3,1 с), не применим: p50 вдвое-втрое выше, а в боевом
режиме она не отвечает в 63% случаев. Выигрыш качества не отличим от шума.

## Приоритет против серебра и золота

Золото не заполнено, поэтому выводов для изменений нет; ниже то, что видно по серебру (оно следует
буквальному чтению таксономии: «жалобы с доказательствами» это p1, без доказательств p3).
Разметка скрытого теста ручная, одно серебро менять таблицу не оправдывает.

- Больше всего расхождений даёт `complaint.admin` (апелляции): серебро ставит p3 в 144 из 180
  тикетов без доказательств, таблица всегда p2. Вариант «апелляция без доказательств p3» даёт точность
  70,0% (было 61,0%). Не менять без золота: апелляция идёт человеку всегда, и p2 осознанно выше p3.
- Правило доказательств: серебро ставит p1 insult/dm/other с доказательствами (`EVIDENCE_BOOST`
  включил бы это): точность 65,9%, macro-F1 0,53 против 0,43; оба варианта вместе 74,9%.
  Решение команды: категория важнее доказательств; серебро его не подтверждает, золото решит.
  Переключатель уже есть (`classify.EVIDENCE_BOOST`), `eval_report.json` и `eval_summary.md` содержат
  таблицу вариантов для золота (`priority.variants` по тем же строкам).
- В серебре p1 только 18% recall при precision 96%: серебро присваивает p1 по доказательствам, таблица по
  категории.
- В выгрузке у всех жалоб есть вложения, а `has_evidence` требует слов или ссылки (18% жалоб), поэтому
  «без доказательств» это не «без вложений».

## Цикл качества

Прочитано 22 случайных черновика и все черновики репортов. Главные три проблемы и что сделано:
1. **Черновик не называет пункт, который назвал бы админ** (recall@draft 0,544). `complaint.invalid`
   и быстрый путь с вложением давали нейтральный ответ без пункта (в 73 тикетах админ назвал пункт, в 0
   черновик). Теперь для этих двух случаев (только при `_has_proof`, ответ человеку) в `cited` кладётся
   подсказка: пункт, который игрок сам написал в жалобе (админ называет его в 61% таких случаев), иначе
   основной пункт второй по вероятности категории нарушения при вероятности ≥ 0,2 (44%). В текст пункт
   не попадает, в `reasons` пометка «подсказка, не подтверждено». recall на valid (in-sample) 0,544 → 0,66; на чистой выборке 0,674.
2. **Тексты репортов копировали опечатки образцов стиля** («Ваше безасие», «Всех втречау») и одно
   нарушение: «лучшие специалисты спешат на помощь» проходило проверку. Промпт требует грамотного
   текста и одного приветствия, проверка кода ловит `спешат на помощь` и `ожидайте помощи`
   (`capability_claim`, `promise_help`); опечаток 2 → 1 на 73.
3. **Неуклюжие шаблоны**: обращение-апелляция «передано администратору, решение принимает
   администратор» и тавтология «описанное нарушение (нарушение правил)». Шаблоны переписаны (ru, uz, kk),
   общие фразы нарушения опускаются.

Языковое правило (см. выше) добавлено по замечанию из живой проверки.

## Решения и отступления от контрактов

- Что настраивалось на valid и потому оптимистично: см. раздел итогов.
- `core/pipeline.py` менялся тремя способами (все с тестами, все описаны выше): подсказка пункта,

- Золото не использовалось: `gold_todo.csv` пуст; блок золота и интеррейтер в отчёте пустые.
