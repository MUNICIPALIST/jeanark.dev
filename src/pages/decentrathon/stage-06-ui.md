**Сделано.**
- `api/auth.py`: `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`. Логин и пароль из
  `settings.jury_login` / `settings.jury_password` (хеши SHA-256 сравниваются `hmac.compare_digest`). Сессия:
  подписанный httpOnly-cookie `copilot_session`, `SameSite=Lax`, 12 часов, HMAC-SHA256 с ключом
  `SESSION_SECRET` (нет ключа: случайный на старте и предупреждение в логе, сессии живут до перезапуска). Флаг
  `Secure` ставится, если `X-Forwarded-Proto: https`. Без `JURY_PASSWORD` вход отключён (503
  `login_disabled`), интерфейс говорит об этом, открытого доступа нет. Неудачные входы: 5 за 5 минут с одного
  адреса (правый элемент `X-Forwarded-For` или сокет), ответ 429 с `Retry-After`; сначала проверяется адрес, потом
  пароль. Общий предел 60 за 5 минут применяется только к неверному паролю: верный пароль общий предел не
  останавливает. Токен сессии несёт случайный `sid` и привязку к паролю: выход заносит `sid` в список отозванных (в БД,
  переживает перезапуск), смена `JURY_PASSWORD` обрывает все сессии.
- Доступ: `/health`, `/auth/*` и статика открыты; `/api/*` только с сессией (иначе 401, в том числе
  для несуществующих путей `/api/...`); `POST /triage` принимает сессию или `X-API-Key`. Без `PUBLIC_MODE` поведение ключа не
  менялось: без `API_KEY` `/triage` открыт, как требует контракт кейса (организаторы могут запускать контейнер у себя).
  Ответ `/triage` теперь несёт заголовки `X-Triage-Latency-Ms`, `X-Triage-Cost-Usd`, `X-Triage-Path`,
  `X-Triage-Model`; тело осталось контрактным. На все ответы добавлены `nosniff`, `X-Frame-Options: DENY`, на
  `/api`, `/auth`, `/triage` `Cache-Control: no-store`.
- `api/store.py`: SQLAlchemy Core, таблица `tickets` в `settings.db_path` (рядом с `telemetry`, отдельная
  таблица). Строка хранит запрос, полный ответ, нормализованный и исходный текст, состояние и решение.
  Исходный черновик (`response.draft_reply.text`) и правка администратора (`edited_text`) лежат раздельно:
  это обучающий сигнал. Правка, равная черновику, сигнал не создаёт. `final_text` заполняется только у
  отправленных. Закрытые (`sent`, `escalated`) обращения менять нельзя (409).
- `api/seed.py` + `api/demo_tickets.json`: 35 выдуманных обращений (ru, uz, kk, ники `Demo_PlayerN`, есть
  kk с подменой букв cp1251). На первом старте каждое проходит `core.pipeline.triage` один раз
  (6 параллельно), результат сохраняется, в телеметрию идёт строка. Повторный старт ничего не вызывает (сид
  идемпотентен по id и возобновляем). Нет ключа или вызов упал: сохраняется безопасный ответ конвейера.
  Сид идёт фоном, очередь отдаёт `seeding: true`. Очередь наполняется только этим файлом.
- `api/tickets.py`: `GET /api/tickets` (фильтры `state`, `priority`, `lang` через запятую, поиск `q` без
  учёта регистра по тексту, исходному тексту, id, категории, языку; сортировка `sort`/`order`; `page`,
  `page_size` до 100; в ответе `total`, `pages`, `counts` по состояниям), `GET /api/tickets/{id}`,
  `POST /api/tickets/{id}/send|edit|escalate` (`send` и `escalate` принимают необязательный `text`),
  `POST /api/tickets` (выдуманное обращение из песочницы, один вызов конвейера, не больше 200),
  `GET /api/metrics`, `GET /api/rules/{ref}`. Отправка только меняет состояние: интеграции с игрой нет, и
  интерфейс об этом пишет.
- `api/metrics.py`: строки те же, что в демо, с целью, весом, значением и источником. Источники по порядку:
  `artifacts/eval_report.json` (читаются пути `gold.*`, затем `silver.*`, `citations.nonexistent_citations`,
  `cost_usd.mean`, `latency_ms.p95`, `routing.needs_human_share`, `n`; плоские имена тоже), затем телеметрия
  (цена, p95) и очередь (доля «нужен человек»). Чего нет, там `null` и «ещё не измерено». Числа по silver
  помечены в колонке «Источник»: это согласие с разметкой LLM, а не точность по эталону.
- `api/rules_view.py`: текст пункта для поповера берётся из локального `rules.json` (`HANDOUT_DIR`) в момент
  запроса, в репозиторий не попадает. Нет файла или пункта: заглушка «Текст пункта недоступен…».
- `api/static.py`: `frontend/dist` на `/` с запасным вариантом SPA. `assets/*` кэшируются на год
  (`immutable`), `index.html` `no-cache`. Пути за пределами `dist` (`..`, `%2e`, симлинки, NUL, `\`) дают
  404, `/api`, `/auth`, `/triage`, `/health` с неизвестным хвостом дают JSON 404, нет сборки: 503 «make ui».
- Фронтенд (`frontend/src`): `api.ts` (клиент, обработка 401 → экран входа с «Сессия истекла»), `types.ts`,
  `demo.ts` (данные демо при `VITE_DEMO=1`), `Login.tsx`, `Queue.tsx` (таблица, панель обращения, поповер с
  загрузкой текста пункта по клику), `Sandbox.tsx`, `Metrics.tsx`, `main.tsx`. Вид и компоненты Cloudscape
  как в демо. Название продукта на экране входа теперь одно (заголовок формы «Вход для жюри»). Состояния
  загрузки, пустой очереди, ошибки с «Повторить». Пагинация, фильтры по приоритету и языку, поиск с задержкой
  300 мс. «Исходный вид» виден, когда нормализованный текст отличается. Flashbar «Правка сохранена как
  обучающий сигнал». Тёмная тема в `localStorage` через try/catch. Песочница вызывает `POST /triage`, показывает
  тело запроса, ответ, задержку (сеть и сервис), стоимость, путь и модель.
- `make ui` (`npm ci && npm run build`), `make ui-demo` (сборка с `VITE_DEMO=1`, для опубликованного демо).
  Зависимость `sqlalchemy>=2.0` в `pyproject.toml`.
- Тесты: `tests/test_api_auth.py`, `tests/test_api_queue.py` (общие фикстуры `tests/apifix.py`): временная БД,
  подделка конвейера из `conftest.py`, без сети. `tests/test_api.py` теперь выставляет временную БД и выключает
  сид (`main.SEED_ON_START`).

**PUBLIC_MODE (публичный инстанс).** `PUBLIC_MODE=1` (по умолчанию выключен):
- `/triage` всегда требует сессию или `X-API-Key`; если нет ни пароля жюри, ни `API_KEY`, он закрыт (401);
- `/docs`, `/redoc`, `/openapi.json` только с сессией (без `PUBLIC_MODE` открыты);
- `/health` отдаёт только `{"status":"ok"}`;
- без `SESSION_SECRET` сервис не стартует;
- потолок расходов на модель за последние 24 часа `DAILY_LLM_USD` (по умолчанию 3): сумма берётся из
  телеметрии (строки до старта процесса) плюс траты этого процесса; при достижении `/triage`, песочница и сид
  отвечают по шаблону без модели (путь `fallback`, в телеметрии `daily_budget`);
- общий предел `/triage` 300 запросов в час (`TRIAGE_GLOBAL_PER_HOUR`).
В обоих режимах: тело запроса не больше 64 КБ (413 отвечает до чтения), `/triage` ограничен по личности
(сессия, иначе ключ, иначе адрес): в публичном режиме 30 в минуту, иначе 1000 в минуту
(`TRIAGE_RATE_PER_MIN`); при превышении 429 с `Retry-After` и телом по контракту (безопасный ответ). Пустой
(только пробелы) текст в `edit`, `send`, `escalate` и `POST /api/tickets` даёт 422. Предел песочницы (200)
проверяется атомарно в той же транзакции, что и вставка.
Сервис рассчитан на **один процесс** (`uvicorn` без `--workers`): пределы запросов и входов хранятся в памяти.
Сид берёт блокировку в БД (строка в `locks`, живёт 10 минут), поэтому несколько процессов не повторяют платные вызовы.
`eval_report.json` читается защитно: не больше 5 МБ, не словарь, нечисловые и невозможные значения (доли вне
0–1/0–100, отрицательные цена и задержка) не показываются.

**Запуск.**
```
make ui                      # собрать интерфейс в frontend/dist
JURY_PASSWORD=<пароль> SESSION_SECRET=<длинная случайная строка> make serve
# публичный инстанс: добавить PUBLIC_MODE=1 DAILY_LLM_USD=3 (SESSION_SECRET обязателен)
# открыть http://127.0.0.1:8000, логин jury (JURY_LOGIN меняет имя)
```
Переменные: `JURY_PASSWORD` (обязательна, без неё вход закрыт), `SESSION_SECRET` (желательна: иначе сессии
сбрасываются при перезапуске и нельзя запускать несколько процессов), `JURY_LOGIN` (по умолчанию `jury`),
`API_KEY` (для `X-API-Key` на `/triage`), `PUBLIC_MODE`, `DAILY_LLM_USD`, `DB_PATH` (очередь и телеметрия), `ARTIFACTS_DIR`, `HANDOUT_DIR` (там
`rules.json` для поповера), `GEMINI_API_KEY` в `.env` для живых ответов при сиде и в песочнице. Порядок
чтения как везде: `.env` главнее окружения. Для HTTPS нужен прокси, который ставит `X-Forwarded-Proto`.

**Решения.**
- Один писатель в БД на процесс (замок) и WAL; телеметрия пишет в тот же файл своим потоком.
- Состояние при сиде берётся из ответа: `is_spam_or_duplicate` → `duplicate`, `needs_human` → `human`, иначе
  `auto`. Дубли сейчас никто не помечает (этап 7), поэтому в очереди их нет.
- `GET /auth/me` без сессии отвечает 401 с телом `{authenticated:false, login_enabled}`, чтобы интерфейс
  знал, показывать ли форму или сообщение об отключённом входе.
- Метрики не подставляют значений по умолчанию. Задержка и цена берутся из отчёта оценки, если он есть,
  иначе из телеметрии живого сервиса (включая сид и песочницу).

**Проверка.** `pytest -q`: 1163 пройдено, 3 пропущено (из них 108 новых в `test_api_auth.py`,
`test_api_queue.py`, `test_api_security.py`). Браузер: сервис на 127.0.0.1 и headless Chrome с Playwright (скрипт во временной
папке вне репозитория): неверный пароль и пустая форма, вход, cookie httpOnly/Lax, очередь, страница 2,
открытие обращения, поповер пункта, правка и её сохранение, отправка, эскалация, текстовый фильтр, пустой
результат, вид «Обработано», исходный вид kk, песочница с задержкой и стоимостью, метрики, тёмная тема после
перезагрузки, истёкшая сессия, выход и 401 на `/api` после него. Сборка демо `VITE_DEMO=1` открылась и показала очередь.

**Не сделано, риски.**
- Кнопки в игру ничего не отправляют, это по условию. Обучающий сигнал только копится в БД, выгрузки нет.
- Пределы входов и запросов в памяти процесса: запускать один воркер.
- Без `PUBLIC_MODE` и без `API_KEY` `/triage` открыт и тратит бюджет модели (так требует контракт кейса); для
  публичного URL включить `PUBLIC_MODE=1`. Дневной потолок читает телеметрию: если удалить файл БД, история трат
  потеряется.
- Размер бандла: около 560 КБ gzip (js 316, css 247), в основном Cloudscape.
- Поповер пункта показывает кусок `rules.json` с сервера: на публичном инстансе без файла правил будет заглушка.
- Формат `eval_report.json` задан этапом 5; если он поменяется, обновить `PATHS` в `api/metrics.py`.
- Кнопки «Добавить в очередь» из песочницы нет, есть только `POST /api/tickets`.
