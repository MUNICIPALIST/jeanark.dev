**Сделано.**
- `cli/label.py`: серебряные метки через OpenAI `gpt-6-luna` (Responses API, `reasoning.effort=none`,
  строгая JSON-схема, `store=false`, 16 параллельных запросов, повторы на 429/5xx, дозапись при
  перезапуске). Команды: `python -m cli.label sample|run --split train|valid [--extra]|gold`.
- `core/classify.py` по контракту: `predict_topk`, `rule_flags`, `extract`, `priority_for`, плюс
  `featurize` и `model_available`. Сети нет. Без `classifier.joblib` работает запасной вариант на
  ключевых словах.
- `cli/build_classifier.py`: обучение на `labels_train`, оценка на `labels_valid`, запись
  `classifier.joblib` и `classifier_metrics.json`.
- `tests/test_classify.py`, `tests/test_label.py`: выдуманные тексты, без данных и сети. Путь модели
  проверяется на игрушечной модели, обучаемой в самом тесте. Полный набор: 555 тестов проходят, 3
  пропущены (нужен настоящий `classifier.joblib`). Регрессии по замечаниям ревью (порог
  доказательств по вложениям, фильтр классов чужого `kind`, шаблоны `\bгк\b` и `деанон`) проверены
  мутациями: каждая ломает тест.

**Артефакты** (только в `ARTIFACTS_DIR`, в git не попадают): `labels_train.jsonl` (9 700),
`labels_valid.jsonl` (1 000), `gold_todo.csv` (300 строк: 200 tune и 100 final; колонки `ticket_id`,
`split`, `kind`, `lang`, `images_count`, тексты, пустые `gold_category` и `gold_priority`,
`first_30_shared` = 1 у первых 30 строк), `gold_silver.csv` (серебряные категория и приоритет по
`ticket_id`, отдельно, чтобы не подсказывать разметчикам), `classifier.joblib`, `classifier_metrics.json`,
`label_usage.json`, `label_sample_train.json` (4 971) и `label_sample_train_extra.json` (4 729). В метках есть лишние столбцы `has_evidence` и `reason`.

**Решения и причины.**
- Модель своя на каждый `kind`: жалоба не может получить категорию репорта. Признаки: TF-IDF
  char_wb 2-5 и слова 1-2 по нормализованному тексту плюс токены `KIND_*`, `LANG_*`, `HAS_URL`,
  `HAS_EVIDENCE`, `NO_LETTERS`, `VERY_SHORT`. Для жалоб выбрана LogisticRegression
  (`class_weight=balanced`), для репортов калиброванный LinearSVC, выбор по macro-F1 на silver valid.
  Выбор между двумя кандидатами делался на тех же данных, где считается метрика, поэтому оценка слегка
  оптимистична.
- Выборка для разметки шла в два захода: 4 971 тикет, стратифицированный по kind, языку и вердикту
  (sqrt-аллокация, принудительные квоты для uz, kk, платежей, аккаунтов, угроз и апелляций), затем
  4 729 дополнительных, в основном жалоб. Причина: на 5 000 меток accuracy жалоб была 0,75, кривая
  обучения росла (0,70, 0,72, 0,75 при 25%, 50%, 100% данных). Редкие `complaint.rmt_ads` и
  `report.payment` добирались по словарю ключевых слов, потому что языковая эвристика даёт kk всего
  у 50 тикетов train.
- Метка описывает запрос игрока, а не исход; ответ админа дан модели только как подсказка.
  Это значит, что часть меток зависит от текста, которого у классификатора на входе нет, и это
  потолок точности.
- `extract`: `has_evidence` истинно при `<url>` в тексте или при вложениях вместе со словами о
  доказательствах. `images_count` сам по себе доказательством не считается. Слова доказательств
  привязаны к началу слова («записался» не запись) и отбрасываются при отрицании («нет доказательств»,
  «без скрина», `dalil yo'q`). Ссылки на пункты проверяет `core.rules.normalize_ref`; без
  `rules.json` берутся цифровые ссылки с префиксом по `SECTION_ALIASES`. Каждый префикс остаётся
  при своём номере («ППЖ 2.1 ЗЗ 1.1» даёт `ЖБ 2.1` и `GZ 1.1`), голый номер в тексте без слова
  «пункт» и суммы вроде «3.5 млн» ссылками не считаются. Ники: допускаются суффикс `_2` и ники
  в нижнем регистре. Загрузка модели однопоточная (замок), параллельные вызовы грузят файл один раз.
- Регулярки флагов проверены по серебряным меткам и сужены: убраны шумные `оплат`, `доступ`,
  `в рл`, `угроза жизни`. Флаг `threat_irl` переписан под высокую точность: нужна связь с реальной
  жизнью или докс/деанон/сватинг, обычные угрозы в игре не срабатывают. Относительно серебряного
  `threat_irl` на train (сэмпл обогащён угрозами): 24 попадания, 4 ложных, 11 пропусков, точность
  0,86, полнота 0,69 (было 8 из 15 и 8 из 35); на valid ложных срабатываний нет (серебряных угроз
  там 2, обе пропущены). Остальные угрозы получают p0 только через `llm_threat`. Флаги `payment` и
  `account` подсказки, на приоритет напрямую не влияют.
- `priority_for`: таблица из docstring модуля. Добавлен переключатель `EVIDENCE_BOOST = False`
  (инсульт, DM и другое с доказательствами поднимаются с p2 до p1). Таксономия относит «жалобы с
  доказательствами» к p1, а пример контракта и решение команды дают p2 для оскорбления со скриншотами.
  Серебряные приоритеты следуют буквальному чтению таксономии, поэтому по умолчанию таблица с ними
  расходится. Переключатель менять только после разметки золотой выборки.

**Как проверить.**
```
export ARTIFACTS_DIR=.../artifacts HANDOUT_DIR=".../handout 2"
python -m pytest -q                      # 60 тестов, без артефактов 1 пропущен
python -m cli.label run --split valid    # затем --split train, --split train --extra
python -m cli.label gold
python -m cli.build_classifier
```

**Почему приоритет не достиг цели.** Цель по приоритету не проверена: серебро не заменяет золотую
выборку, и пока людей нет в цикле, её нельзя считать ни достигнутой, ни окончательно проваленной.
Разбор расхождений таблицы с серебром (по ревью): около 162 апелляций (серебро p3, таблица p2),
около 118 расхождений от доказательств (серебро p1, таблица p2) и около 99 случаев, где само
серебро непоследовательно.
1. Серебряный p1 ставится «жалобам с доказательствами» (букв. таксономия), а таблица по решению
   команды даёт p2 для оскорблений и DM. С `EVIDENCE_BOOST=True` macro-F1 растёт до 0,43 на
   предсказанной и 0,59 на серебряной категории.
2. Серебряный приоритет оскорблений без доказательств почти случаен (в valid таких 210: p2 у 80, p3 у 99,
   p1 у 30, p0 у 1), таблица детерминирована и этот шум не берёт. Для апелляций
   (`complaint.admin`, 20% valid) серебро чаще ставит p3, таблица по контракту ставит p2.
3. p0 в valid всего 3 тикета, F1 по p0 равен 0 на предсказанной категории и 0,4 на серебряной. В скрытом тесте из 500 тикетов
   их будет 1-2, macro-F1 по приоритету будет очень шумным.
Потолок «буквальное чтение» (поднять с доказательствами, апелляции без доказательств в p3) на серебряной
категории около 0,60. Реальную цель можно проверить только на золотой выборке.

**Не сделано и риски.**
- Золотая выборка не размечена людьми: `gold_todo.csv` ждёт двух разметчиков (общие первые 30 строк
  для согласия). `python -m cli.label gold` не перезапишет файл без `--force`, строки с заполненным
  золотом `--force` сохраняет. После неё пересчитать
  точность, решить `EVIDENCE_BOOST` и судьбу апелляций в p2.
- Категории `complaint.other` и `complaint.invalid` различаются плохо (F1 0,50 и 0,64): серебро там
  шумное, часть меток опирается на ответ админа. В конвейере берём top-3 из `predict_topk`, а решение
  оставляем LLM.
- Казахский: в train только 50 тикетов с языком kk, качество на kk не измерено (в valid 7).
- Дедупликация по точному тексту при выборке, повторы с мелкими отличиями остаются.
- Модель обучена только на train; valid используется для оценки. Переобучение на train+valid не
  делали.
- Следующему этапу: `predict_topk(text, kind, k)` возвращает вероятности по категориям своего kind;
  `rule_flags['threat_irl']` сразу даёт p0, поэтому регулярки лучше не расширять без проверки
  ложных срабатываний. `--extra` теперь читает свой кэш и не перетягивает выборку заново; обрезанная
  последняя строка при возобновлении отбрасывается.
