## Две роли на сайте

На демо-инстанс (выключен) две вкладки входа.

| Вкладка | Как войти | Что открыто |
|---|---|---|
| **Жюри** | кнопка «Войти», логин и пароль не нужны | очередь со статистикой, «Проверить обращение», метрики: только выдуманные обращения и номера пунктов правил |
| **Команда** | логин `dev`, пароль у команды, своё имя | всё то же, текст правил, разметка настоящих тикетов, проверка языка, прогресс и результаты |

Прямые ссылки: `/admin` очередь, `/check` проверка обращения, `/metrics` метрики, `/label` разметка, `/review` проверка языка,
`/dashboard` результаты. Сервер проверяет роль на каждом запросе, поэтому экраны команды по ссылке без входа не откроются.

## Быстрый запуск: Linux, macOS, Windows

Одна команда создаёт окружение, ставит зависимости и запускает сервис. Ключ, сеть и GPU для работы не нужны, режим `LLM_BACKEND=none`.

```bash
git clone -b main https://github.com/BAITC-Hacks/hack-d25062d8-vencera.git
cd hack-d25062d8-vencera
```

| Что сделать | Linux и macOS | Windows |
|---|---|---|
| проверить на трёх выдуманных тикетах | `./run.sh` | `.\run.bat` |
| прогнать свой файл JSONL | `./run.sh predict in.jsonl out.jsonl` | `.\run.bat predict in.jsonl out.jsonl` |
| открыть сайт на http://127.0.0.1:8000 | `./run.sh site` | `.\run.bat site` |
| запустить в Docker | `./run.sh docker` | `.\run.bat docker` |
| прогнать тесты | `./run.sh test` | `.\run.bat test` |

Первый запуск занимает около минуты. На сайте нажмите «Войти», очередь наполнится выдуманными обращениями.

**Папка кейса.** Цитаты пунктов берутся из `rules.json`. Положите папку `handout` рядом с репозиторием или укажите её путь:

```bash
export HANDOUT_DIR="/путь/к/handout"          # Linux и macOS
```

```powershell
$env:HANDOUT_DIR = "C:\путь\к\handout"       # Windows
```

Без неё сервис работает, но черновики не цитируют пункты.

**Что установить.** Для `run` нужен Python 3.12 или новее, для `site` ещё Node 22, для `docker` только Docker.

| Система | Python | Node | Docker |
|---|---|---|---|
| Ubuntu, Debian | `sudo apt install python3.12 python3.12-venv` | `sudo snap install node --classic --channel=22` | `sudo apt install docker.io docker-compose-v2` |
| macOS | `brew install python@3.12` | `brew install node@22` | Docker Desktop |
| Windows | `winget install Python.Python.3.12` | `winget install OpenJS.NodeJS.LTS` | Docker Desktop |

Скрипты для Linux и macOS проверены на macOS на чистой копии репозитория. `run.ps1` на настоящем Windows не запускался. Если он не сработает, используйте `.\run.bat docker`.

Подробный разбор, команды вручную и частые ошибки: разделы ниже.

## Для жюри: проверка за 10 минут

Всё ниже работает **без API-ключа, без сети (после установки) и без GPU**, цена $0. Сайт: демо-инстанс (выключен)

### 1. Самый быстрый путь: сайт

Откройте демо-инстанс (выключен) на вкладке «Жюри» нажмите «Войти». Ни логина, ни пароля не нужно.

| # | Что сделать | Какой результат хороший |
|---|---|---|
| 1 | В очереди посмотрите карточку «С чего начать» и панель статистики над списком | Видно, сколько обращений всего, сколько ждут администратора, разбивку по срочности (p0-p3) и долю обработанных. Выдуманных обращений 35, настоящих игроков на сайте нет |
| 2 | Откройте обращение из списка (вкладка «Ждут») | Справа: текст игрока, категория, срочность, черновик ответа на языке игрока. Раздел «Почему так» показывает шаги, найденные факты и причины |
| 3 | Найдите в черновике или в причинах номер пункта правил, например `ОП 2.1` | Номер совпадает с пунктом в `rules.json` кейса и подходит к нарушению. Для платежей и аккаунта пункт не нужен («Пункты правил не нужны»), обращение передано администратору |
| 4 | Нажмите «Отправить» или «Эскалировать» | Статус меняется, счётчик «Осталось» уменьшается, открывается следующее обращение. В игру ничего не уходит, это написано под кнопками |
| 5 | «Проверить обращение»: выберите пример «Оскорбление в чате», нажмите «Разобрать обращение» | Категория `complaint.insult`, приоритет, черновик с цитатой пункта, блок «Почему так решено». Вводите только выдуманный текст |
| 6 | «Метрики» | Ответы на три вопроса: цена и скорость, выдумывает ли сервис правила, передаёт ли важное человеку. Значения идут с пометками «в норме» или «ниже цели», недостигнутая цель не скрыта. Если отчёта оценки нет, написано «ещё не измерено»: итоговые числа смотрите в разделе 4 |
| 7 | В карточке обращения откройте блок «Мои заметки» и добавьте заметку | Заметку видите только вы: другие посетители и команда её не получают. До 1000 символов, до 20 на обращение; заметки не входят в ответ игроку и не меняют статус |
| 8 | В верхнем меню нажмите «Пройти обучение» | Короткое обучение на трёх вымышленных обращениях в вашем браузере: сервер и модель не вызываются, учебные метрики выдуманы. Выход возвращает на прежний экран. Подробно: внутренний документ |

Примерно 9 из 10 обращений ждут человека: так задумано, а не сбой (раздел 4).

### 2. Запуск у себя без ключа

Нужны `git`, Python 3.12 или новее (`python3 --version`) и папка кейса (`handout`) с файлами `rules.json` и
`taxonomy.json`: из `rules.json` берутся цитаты пунктов правил. Репозиторий закрытый, нужен доступ к нему.

**Способ А. Консоль, `make predict`** (контракт кейса: файл JSONL на входе, файл JSONL на выходе):

```bash
git clone -b ja-track-3 https://github.com/BAITC-Hacks/hack-d25062d8-vencera.git
cd hack-d25062d8-vencera
python3 -m venv .venv && source .venv/bin/activate
make install
export HANDOUT_DIR="/путь/к/handout"        # папка, где лежит rules.json
cat > my_tickets.jsonl <<'EOF'
{"ticket_id": "my-1", "kind": "complaint", "messages": [{"role": "player", "text": "Игрок Demo_Player7 оскорблял меня и мою семью в общем чате, скрины есть, п. 2.1 ОП", "attachments": 2}]}
{"ticket_id": "my-2", "kind": "report", "messages": [{"role": "player", "text": "Как восстановить доступ к клану, если лидер давно не заходил?"}]}
{"ticket_id": "my-3", "kind": "complaint", "messages": [{"role": "player", "text": "Demo_Player3 chatda meni haqorat qildi, skrinshot yubordim", "attachments": 1}]}
EOF
make predict IN=my_tickets.jsonl OUT=pred.jsonl
python -c "import json; [print(r['ticket_id'], r['lang'], r['category'], r['priority'], r['needs_human'], r['draft_reply']['cited']) for r in map(json.loads, open('pred.jsonl'))]"
```

Ожидаемый вывод `make predict` (первая строка это сама команда, дальше stderr; первая строка сервиса называет режим):

```
python -m cli.predict --in "my_tickets.jsonl" --out "pred.jsonl"
mode: none - offline: no model, no network, no key (classifier, rule choice and templates only)
note: knowledge base not built: questions are handed to an administrator (make build HANDOUT_DIR=... builds it)
note: Uzbek vocabulary not built: Uzbek detection is slightly weaker (make build HANDOUT_DIR=... builds it)
3/3
```

Две строки `note:` нормальны: это необязательная база знаний (`make build HANDOUT_DIR=...`, около 2 минут, нужен
`tickets_train.jsonl.gz` в папке кейса). Вывод последней команды, три строки вида
`my-1 ru complaint.insult p2 True ['ОП 2.1']`: язык, категория, приоритет, нужен ли человек, цитируемые пункты.
В `pred.jsonl` одна строка на тикет в том же порядке, поля контракта: `lang`, `category`, `priority`,
`is_spam_or_duplicate`, `extracted`, `draft_reply` (`lang`, `text`, `cited`), `needs_human`, `confidence`, `reasons`;
рядом `pred.jsonl.telemetry.jsonl` без текстов.

**Свои тикеты.** Подставьте свой файл: `make predict IN=ваш.jsonl OUT=pred.jsonl`. Одна строка это один JSON-объект.
Обязательны только `kind` (`complaint` или `report`) и `messages`; `ticket_id`, `region`, `rule_refs_raw`,
`images_count` и остальные поля выгрузки необязательны. Пример строки (текст выдуманный):

```json
{"ticket_id": "t-1", "kind": "complaint", "messages": [{"role": "player", "text": "Demo_Player9 использует читы, стреляет через стены, запись есть", "attachments": 1}]}
```

Нечитаемая строка получает безопасный ответ и счётчик на stderr, а не остановку. Нет файла, пустой файл или ни одной
строки-тикета: код выхода 2 и понятное сообщение.

**Способ Б. Сервис с интерфейсом, `make serve`** (нужен Node 22 с `npm`, только для сборки интерфейса):

```bash
make ui                                      # собирает frontend/dist, 1-2 минуты
make serve                                   # http://127.0.0.1:8000
```

Сервис стартует за 5-10 секунд: ждите строку `Uvicorn running on http://127.0.0.1:8000`. Строка `SESSION_SECRET is not set` нормальна
(сессии живут до перезапуска). Откройте http://127.0.0.1:8000, на вкладке «Жюри» нажмите «Войти» и пройдите шаги из раздела 1; очередь
наполнится 35 выдуманными обращениями за несколько секунд. Тот же запрос по контракту (в другом окне консоли):

```bash
curl -s -X POST http://127.0.0.1:8000/triage -H 'Content-Type: application/json' -d '{"kind": "complaint", "messages": [{"role": "player", "text": "Demo_Player7 оскорблял меня в общем чате, скрины есть", "attachments": 2}]}'
curl -s http://127.0.0.1:8000/health         # в ответе "llm_backend":"none", "rules":true
```

Без `make ui` страница `/` отвечает 503 «Интерфейс не собран», а `/triage`, `/docs` и `/health` работают. Другой порт:
`make serve PORT=8765`.

**Способ В. Docker** (ничего ставить на хост не нужно, интерфейс собран в образ; нужен Docker с `compose`):

```bash
git clone -b ja-track-3 https://github.com/BAITC-Hacks/hack-d25062d8-vencera.git
cd hack-d25062d8-vencera
mkdir -p artifacts-runtime && cp "/путь/к/handout/rules.json" "/путь/к/handout/taxonomy.json" artifacts-runtime/
docker compose -f docker-compose.local.yml up --build        # http://127.0.0.1:8000, остановка: Ctrl+C
```

Первая сборка занимает несколько минут. Готово, когда в логе есть `Uvicorn running on http://0.0.0.0:8000`; проверка:
`curl -s http://127.0.0.1:8000/health` отвечает `"llm_backend":"none"` и `"rules":true`. Остановить и убрать контейнер:
`docker compose -f docker-compose.local.yml down -v`.

Тот же `make predict` без Python на хосте (файл `my_tickets.jsonl` из способа А):

```bash
mkdir -p io && cp my_tickets.jsonl io/
make predict-docker DIR=io IN=my_tickets.jsonl OUT=pred.jsonl     # результат: io/pred.jsonl
```

### 3. Какие переменные указать

**Ничего не обязательно.** Для `make predict` нужна только `HANDOUT_DIR`, и то лишь ради цитат пунктов правил: без неё
сервис отвечает, но не цитирует пункты и пишет об этом предупреждением. Файл `.env` необязателен: `cp .env.example .env`,
затем нужные строки (пустые значения ничего не меняют). `.env` важнее переменных оболочки и в git не попадает.

| Переменная | Нужна? | По умолчанию | Что делает |
|---|---|---|---|
| `HANDOUT_DIR` | для цитат правил | `../handout 2` рядом с репозиторием | папка кейса с `rules.json` и `taxonomy.json` |
| `GEMINI_API_KEY` | нет | пусто | с ключом (и `LLM_BACKEND=auto`) черновики пишет Gemini; без ключа офлайн-режим |
| `LLM_BACKEND` | нет | `auto` | `none`: всегда без модели и сети; `gemini`: только модель; `auto`: по наличию ключа |
| `OPENAI_API_KEY` | нет | пусто | запасная модель и разметка (`cli.label`); сервису и `make predict` не нужна |
| `ARTIFACTS_DIR` | нет | `./artifacts` | куда `make build` пишет базу знаний и откуда сервис её читает |
| `API_KEY` | нет | пусто | если задан, `POST /triage` требует заголовок `X-API-Key` |
| `SESSION_SECRET` | нет | случайный при старте | подпись сессий входа в интерфейс |
| `DB_PATH` | нет | `runs/copilot.sqlite` | SQLite с очередью обращений и телеметрией |
| `PORT`, `HOST`, `PY` | нет | `8000`, `127.0.0.1`, `python` | переменные `make`: `make serve PORT=8765`, `HOST=0.0.0.0` открывает сервис в сети, `PY=/путь/к/python` выбирает интерпретатор |

Остальные переменные (модели, таймауты, режим публичного инстанса) описаны в разделе «Настройка» ниже. Одноразово без файла:
`HANDOUT_DIR=/путь/к/handout make predict IN=... OUT=...`. Docker читает `.env` из корня репозитория сам (compose подставляет
`GEMINI_API_KEY`, `OPENAI_API_KEY`, `SESSION_SECRET`, `API_KEY`); `HANDOUT_DIR` ему не нужен, правила он берёт из `artifacts-runtime`.

### 4. Что проверить по критериям кейса

| Критерий | Как проверить | Что должно быть |
|---|---|---|
| Контракт `POST /triage` | команда `curl` из раздела 2 или «Проверить обращение» на сайте | ответ с полями `lang`, `category`, `priority`, `extracted`, `draft_reply`, `needs_human`, `confidence`, `reasons` |
| `make predict IN=... OUT=...` | раздел 2, способ А | одна строка ответа на строку входа, в том же порядке |
| Цитаты правил | поле `draft_reply.cited` и текст черновика | пункт вида `ОП 2.1` есть в `rules.json`; выдуманных цитат 0 (проверка кодом, а не моделью): 0 из 118 черновиков с цитатой в офлайн-режиме на чистой выборке из 300 тикетов |
| Эскалация | категории платежа, аккаунта и апелляции | `needs_human: true` и фраза о передаче администратору |
| Без ключа | любой способ из раздела 2 | первая строка `mode: none - offline` или `"llm_backend": "none"` в `/health` |

Честные числа (всё из [docs/report.md](/decentrathon/report/), разделы 6.1 и 6.5, чистая выборка из 300 тикетов, офлайн-режим на коде этапа 38; Gemini на этом коде не перегонялся):

| Показатель | Значение | Цель | Статус |
|---|---|---|---|
| recall пункта правил в черновике, все поля выгрузки | 0,674 | 0,70 | **не достигнута** |
| recall пункта правил, только поля контракта (`--contract-only`) | 0,620 | 0,70 | **не достигнута** |
| несуществующих цитат | 0 | 0 | достигнута |
| точность категории по разметке людей (n=185) | 64,9% (95%: 58–71%) | нет | первая проверка на людях |
| точность приоритета по разметке людей, macro-F1 | 69,7%, 0,460 | нет | люди сами совпадают в 48,1% |
| `needs_human` | 92,7% (офлайн), 90,3% (Gemini) | нет | справочно |
| цена на тикет, задержка p95 | $0 и 4 мс (офлайн) | нет | справочно |

Границы: люди разметили только 185 из 300 тикетов, два разметчика сами расходятся (раздел 6.4 отчёта). Согласие категории
с «серебром» (разметкой модели) 0,801 на 1000 тикетах valid, это согласие с моделью, а не точность. Проверяющие чаще всего замечают содержание, а не язык, и сильно расходятся между собой, раздел 12 отчёта.
Полный список: [раздел «Ограничения» ниже](#ограничения) и [docs/report.md](/decentrathon/report/), раздел 12.

### 5. Если что-то не работает

| Что видите | Причина и что делать |
|---|---|
| `python: command not found` или `No module named ...` (`make: *** [predict] Error 127`) | не включено окружение: `source .venv/bin/activate` (или `make install PY=/путь/к/python`) |
| `WARNING: rules.json not found ... drafts cite no rule point` | `HANDOUT_DIR` не указывает на папку с `rules.json`: `export HANDOUT_DIR="/путь/к/handout"` (путь с пробелом в кавычках). В Docker: скопируйте `rules.json` и `taxonomy.json` в `artifacts-runtime/` (раздел 2, способ В) |
| первая строка `mode: gemini - hosted model` вместо `mode: none` | в окружении есть `GEMINI_API_KEY` (оболочка или `.env`): для офлайн-режима добавьте `LLM_BACKEND=none`, например `LLM_BACKEND=none make predict IN=... OUT=...` |
| на `http://127.0.0.1:8000` текст «Интерфейс не собран: выполните make ui» (503) | не выполнен `make ui` (нужен Node 22); `/triage` и `/health` работают и без него |
| `make serve` падает с `address already in use` (`Error 3`) | порт 8000 занят: `make serve PORT=8765` |
| `error: input has no tickets` и код выхода 2 | файл пустой или не JSONL: одна строка это один JSON-объект с `kind` и `messages` |

Сервис триажа обращений игроков Grand Mobile (кейс 03, Decentrathon 6.0). Он принимает жалобу или
репорт, определяет язык, категорию и приоритет, достаёт факты (ник, номера пунктов, наличие
доказательств) и пишет черновик ответа на языке игрока с цитатой пункта правил. Цитата может быть
только пунктом из найденного списка, а обещания и утверждения о скриншотах отсекает код, не модель.
Если нужен человек, сервис говорит об этом в `needs_human`: на проверенных выборках это 89-91% тикетов.

Полный отчёт с метриками, ограничениями и примерами: [docs/report.md](/decentrathon/report/).

## Запуск сервиса

Нужен Python 3.12+. Цели `make` берут `python` из PATH, поэтому сначала создайте и включите виртуальное
окружение (или передайте интерпретатор: `make install PY=/путь/к/python`):

```bash
python3.12 -m venv .venv && source .venv/bin/activate
make install          # pip install -e ".[dev]"
make serve            # http://127.0.0.1:8000 (HOST, PORT переопределяются: make serve PORT=8765)
```

Если вам передали архив артефактов `artifacts-runtime.tgz`, распакуйте его в `ARTIFACTS_DIR` до `make serve`
и `make predict` (по умолчанию `./artifacts`; `rules.json` и `taxonomy.json` лежат в архиве):

```bash
mkdir -p artifacts && tar -xzf artifacts-runtime.tgz -C artifacts
```

`make serve` слушает только `127.0.0.1`; чтобы открыть сервис в сети, добавьте `HOST=0.0.0.0`. Ключ модели
передают переменной окружения или файлом `.env`: `GEMINI_API_KEY=<ключ> make serve`. Страница `/` (интерфейс
админа) появится после `make ui` (нужен Node 22 и `npm`). Жюри входит без пароля (`JURY_OPEN`, по умолчанию включён); команде
нужен `DEV_PASSWORD`. С `JURY_OPEN=0` пароль жюри `JURY_PASSWORD` нужен снова.
Без `make ui` страница `/` отвечает 503 «Интерфейс не собран», а `/triage`, `/docs` и `/health` работают.

Запрос (тикет выдуманный):

```bash
curl -s -X POST http://127.0.0.1:8000/triage -H 'Content-Type: application/json' -d '{
  "kind": "complaint",
  "messages": [{"role": "player", "text": "Demo_Player7 оскорблял меня и мою семью в чате, скрины есть, 2.1 ОП", "attachments": 2}]
}'
```

Пакетный режим (один тикет на строку JSONL, один ответ на строку в том же порядке; рядом пишется
`pred.jsonl.telemetry.jsonl` без текстов):

```bash
make predict IN=tickets.jsonl OUT=pred.jsonl
```

Проверки:

```bash
make test             # pytest; не требует данных, артефактов и сети
make ci                # pytest, сборка и тесты фронтенда (npm test, нужен Node 22.13+), проверка скриптов
make eval             # прогон 1000 тикетов valid: нужны HANDOUT_DIR, ключ, около $0.5 и 3-4 минуты
make eval ARGS="--limit 20 --seed 1"   # малый прогон для проверки установки
make eval ARGS="--limit 100 --contract-only"   # только kind и messages, как в контракте (без региона, ника, rule_refs_raw)
```

`make eval` перезаписывает `ARTIFACTS_DIR/eval_report.json`. Чтобы этого не было, добавьте
`--report путь.json --summary путь.md`. Как вписать ручную разметку и пересчитать точность:
раздел «Проверка на ручной разметке» в [docs/report.md](/decentrathon/report/).

Без ключа модель не вызывается совсем: работает офлайн-режим (`LLM_BACKEND=none`): категорию даёт
классификатор, пункт правил выбирается кодом, фраза о нарушении берётся из таблицы, ответы на репорты это
шаблоны и ответы базы знаний. Ключ не нужен ни для `make predict`, ни для проверки жюри; что даёт офлайн-режим и сколько качества он теряет по сравнению с Gemini: [docs/stages/17b-local-mode.md](/decentrathon/stage-17b-local-mode/). Ключ кладут в
`.env` (шаблон `.env.example`) только чтобы включить Gemini; `.env` в git не попадает и важнее переменных оболочки.

## Модели и артефакты

В репозитории лежит только то, в чём нет текста игроков и правил: `models/classifier.npz` (хешированные
признаки и линейная модель, массивы чисел без pickle) и `models/category_rules.json` (номера пунктов и счётчики
по категориям). Всё остальное, что выведено из тикетов, остаётся вне репозитория в `ARTIFACTS_DIR`: база знаний
(`kb.json`, `kb_index.joblib`), образцы стиля, словарь узбекского и серебряные метки. Правила и таксономия
читаются из `HANDOUT_DIR`.

- `make build HANDOUT_DIR=...` пересобирает базу знаний, словарь узбекского, образцы и карту пунктов только из
  папки кейса, без ключа и сети. Необязательно: без него вопросы уходят администратору.
- `make train` переобучает классификатор по серебряным меткам (`labels_train.jsonl`, их нет в репозитории;
  как они сделаны, см. [docs/stages/02-classify.md](/decentrathon/stage-02-classify/)). Без меток цель сообщает, что
  делать нечего: модель в репозитории это результат этого шага.

Без `models/classifier.npz` работает запасной путь на ключевых словах, без `rules.json` черновики не цитируют
пункт (и это написано в предупреждении). `GET /health` показывает режим (`llm_backend`) и найденные файлы.

## Архитектура

Порядок обработки: убрать сообщения админа, нормализовать текст и язык, классификатор (топ-3 своего
вида), флаги и факты, выход без модели или один вызов модели по схеме с закрытым списком пунктов,
сборка текста по ветке, проверка кодом, приоритет. Ответ есть всегда: при сбое отдаётся безопасный
шаблон.

| Модуль | Что делает |
|---|---|
| `core/normalize.py` | язык по тексту (без региона), таблица замен cp1251 из ТЗ (только для казахского), очистка текста |
| `core/rules.py` | 266 пунктов правил, нормализация номеров и сокращений разделов |
| `core/classify.py`, `core/hashclf.py` | локальный классификатор по виду тикета (хеш-признаки, `.npz` из чисел), регулярные флаги, `extracted`, таблица приоритета |
| `core/offline.py`, `core/mode.py` | ответ без модели (выбор пункта, фразы, база знаний), описание режима для `make predict` и `/health` |
| `core/context.py`, `core/kbprep.py` | кандидаты пунктов, образцы стиля, поиск по базе знаний, глоссарий uz и kk |
| `core/templates.py` | шаблоны ru, uz, kk: жалоба по существу (3 режима), безопасный ответ, быстрый ответ |
| `core/draft.py` | вызов Gemini по схеме с enum, повтор при задержке, запасная модель, потолок цены |
| `core/guard.py` | проверка кодом: цитаты, обещания, утверждения о скриншотах, язык и письмо |
| `core/pipeline.py` | ветки обработки, правила `needs_human`, бюджет времени, запасные пути |
| `core/dedupe.py` | дубликаты и спам в окне часа (нужен `reporter_hash`) |
| `core/suggest.py`, `cli/suggest.py` | предложения новых шаблонов по кластерам (человек принимает) |
| `core/telemetry.py` | SQLite: путь, токены, цена, задержка, коды проверки, без текстов |
| `api/` | FastAPI: `/triage`, `/health`, вход с тремя ролями, очередь, метрики, разметка (`labels.py`), проверка языка (`review.py`), панель разработчика (`dashboard.py`), предел расходов |
| `cli/predict.py`, `cli/eval.py`, `cli/compare.py` | `make predict`, `make eval`, сравнение моделей и режимов |
| `cli/label.py`, `cli/build_*.py` | серебряная разметка, обучение классификатора (`make train`) и сборка контекста (`make build`); `cli/build_review.py tickets` и `items`: выдуманные обращения и тексты для проверки языка |
| `frontend/` | интерфейс на Cloudscape: очередь, черновик, отправить, править, эскалировать; «Разметка», «Проверка языка», «Прогресс и результаты» по ролям |

## Настройка

Порядок чтения: `.env`, затем окружение, затем значение по умолчанию.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_BACKEND` | `auto` | `auto`: Gemini при наличии ключа, иначе `none`; `none`: без модели, офлайн; `local`: малая модель на этой машине (необязательно); `gemini` |
| `GEMINI_API_KEY` | нет | ключ платного тарифа Gemini; без него (при `auto`) сервис работает офлайн |
| `CLASSIFIER_PATH`, `MODELS_DIR` | `models/classifier.npz`, `./models` | где лежат файлы модели |
| `OPENAI_API_KEY` | нет | запасная модель и разметка (`cli.label`); для работы сервиса не нужен |
| `MODEL_DEFAULT`, `MODEL_MINORITY` | `gemini-3.5-flash-lite` | основная модель, для uz и kk |
| `MODEL_FALLBACK` | `gpt-6-luna` | запасная модель |
| `DRAFT_MODE` | `neutral` | `neutral`, `conditional`, `approved`: как жалоба по существу говорит о санкции; по ответу организаторов санкции в тексте игрока нет, `conditional` и `approved` остались флагами кода |
| `KK_TABLE` | `tz` | таблица замен cp1251 для казахского: `tz` (из ТЗ, ответ организаторов), `data` (выведена из данных, не рекомендуется) |
| `LLM_TIMEOUT_S`, `LLM_HEDGE_AFTER_S` | 3.5, 2.0 | таймаут вызова, повтор запроса при задержке |
| `TOTAL_BUDGET_S`, `LLM_CONCURRENCY` | 4.5, 24 | бюджет времени на тикет, предел параллельных вызовов |
| `ARTIFACTS_DIR`, `HANDOUT_DIR` | `./artifacts`, `../handout 2` | артефакты и каталог с `rules.json` |
| `DB_PATH` | `runs/copilot.sqlite` | очередь админа и телеметрия |
| `JURY_OPEN` | `1` | жюри входит без пароля (вкладка «Жюри», одна кнопка «Войти»); `0` возвращает вход по паролю. Открытая сессия жюри не получает ни одной строки из данных кейса, см. «Роли и данные» |
| `JURY_LOGIN`, `JURY_PASSWORD` | `jury`, нет | роль «жюри»: очередь, проверка обращения, метрики. Пароль нужен только при `JURY_OPEN=0` |
| `DEV_LOGIN`, `DEV_PASSWORD` | `dev`, нет | роль «разработчик»: всё, что видит жюри, плюс разметка настоящих тикетов, проверка языка и панель результатов; без пароля роль выключена |
| `OPEN_LOGINS_PER_HOUR_PER_IP` | 300 | входов жюри без пароля в час с одного адреса |
| `GOLD_FILE` | `/srv/private/gold_todo.csv` | файл настоящих тикетов для разметки (только роль `dev`); читается при старте, в образ и в git не попадает |
| `SESSION_SECRET` | случайный на старте | подпись сессий; в `PUBLIC_MODE` обязателен |
| `API_KEY` | нет | если задан, `/triage` требует заголовок `X-API-Key` |
| `PUBLIC_MODE` | `0` | публичный инстанс: `/triage` и `/docs` только с входом, `/health` минимальный |
| `DAILY_LLM_USD` | `3` в `PUBLIC_MODE` | потолок трат на модель за 24 часа. В `PUBLIC_MODE` всегда; вне его только если задан явно. |
| `QUARANTINE_MODE` | `0` | `1`: ни одно обращение не идёт в модель (`docs/security.md`) |
| `TRIAGE_RATE_PER_MIN`, `TRIAGE_GLOBAL_PER_HOUR` | 1000 (30 в `PUBLIC_MODE`), 300 | пределы запросов к `/triage` |
| `DEDUPE` | `1` | `0` выключает поиск дубликатов |

## Роли и данные

Роли: `dev` и `jury`. Жюри входит без пароля (`JURY_OPEN`, по умолчанию включён), у `dev` свой пароль; роль `dev` без пароля выключена.
Разработчик при входе называет имя (до 60 знаков). Настоящие тикеты есть только в экране «Разметка» и только у роли `dev`; жюри их не получает ни
в каком ответе. «Проверка языка» на выдуманных обращениях (`api/review_items.json`) есть у роли `dev`, на всех трёх языках. Роли «тестер» больше нет:
её голоса остались в базе, в панели результатов и в выгрузках. Подробности: `docs/stages/15-roles-review.md`, `docs/stages/23-open-jury.md`.

Вход открыт, поэтому открытая сессия жюри не получает ничего из данных кейса: ни текста пунктов правил (`/api/rules/...` отвечает 403,
в интерфейсе остаётся номер вроде `ОП 2.1`), ни санкций из правил, ни ответов из базы знаний, ни образцов ответов админов. На публичном
инстансе (`PUBLIC_MODE=1`) при открытом жюри база знаний и образцы не используются вовсе: вопрос уходит админу, как в `make predict` без
базы знаний, а режим черновика всегда `neutral`. Обращения, засеянные раньше с моделью, при старте один раз переписываются офлайн-конвейером
(`api/rewrite.py`, без вызова модели; голоса и разметка не затрагиваются), а всё, что написано не офлайн-конвейером, жюри видит как нейтральный ответ.
Команда (`dev`) видит текст правил.

## Безопасность

Модель угроз по STRIDE и OWASP Top 10 for LLM (2025), порядок действий при атаке и остаточные риски: [docs/security.md](/decentrathon/security/).
Файл для OWASP Threat Dragon: `docs/threat_dragon_model.json`.

- Инъекции: текст игрока идёт в недоверенных блоках, ответ по строгой схеме, `core/suspicious.py` отмечает попытки на ru, kk, uz, en.
  Подозрительное обращение стоит в очереди выше и несёт метку; контракт `/triage` не меняется.
- Правила: ответ ссылается только на пункты из контекста тикета (`core/guard.py`), 0 выдуманных цитат.
- Персональные данные: телефоны, e-mail, карты, IP и ссылки маскируются перед любой внешней моделью (`core/pii.py`), телеметрия без текстов.
- Бюджет: $0,002 на тикет, дневной потолок `DAILY_LLM_USD`, лимиты запросов (`api/limits.py`).
- Вывод: ответ со ссылкой, контактом или мессенджером отклоняется, в том числе с обходами (`core/guard.py`).
- Аудит: журнал `audit_log` только на добавление, триггеры SQLite запрещают правку; просмотр у `dev`.
- Карантин: `QUARANTINE_MODE=1` отключает внешнюю модель, карантин автора идёт через API только у `dev`.

## Ограничения

- Золотой (человеческой) разметки категории и приоритета нет. Все метрики точности в отчёте посчитаны
  по серебру, то есть по мнению модели, и точностью по эталону не являются.
- Часть метрик получена на тех же 1000 тикетах, на которых настраивался код. Чистая выборка из 300
  тикетов не содержит категорий.
- Казахский почти не измерен (7 тикетов в valid). Носители проверили малую часть текстов uz и kk; ответы можно оценить на сайте («Проверка языка»).
- Сервис рассчитан на один процесс: пределы запросов и дубликаты хранятся в памяти.
- Кнопки интерфейса в игру ничего не отправляют, они меняют состояние в очереди и сохраняют правки.

Полный список рисков: [docs/report.md](/decentrathon/report/), раздел «Ограничения и честные риски».
