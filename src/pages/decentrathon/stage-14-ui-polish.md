**Проблема.** Страница «Песочница /triage» была похожа на инструмент разработчика (путь API в названии, сырое тело запроса,
JSON вместо результата). Очередь показывала половину экрана под панелью и требовала прокрутки двух областей, метрики
были таблицей с «p95», «macro-F1» и именами файлов, понятной только разработчику.

**Сделано.** Только `frontend/` и документы; поведение API не менялось, добавлены только новые поля в `GET /api/metrics`.
- **«Проверить обращение»** (маршрут `#check`, старый `#triage` открывает очередь; `/triage` нет ни в меню, ни в заголовках).
  Слева ввод: Select с примерами («Оскорбление в чате», «Жалоба на читы», «Жалоба на узбекском», «Жалоба на казахском»,
  «Платёж не пришёл», «Несогласие с баном», «Просьба о помощи», «Пустое сообщение»), Textarea, SegmentedControl «Жалоба / Репорт»,
  Toggle вложения, кнопка «Разобрать обращение» с загрузкой. Выбор примера только заполняет форму, запускает кнопка. Справа
  результат: строка вердикта (срочность словом и кодом, название категории, «Нужен человек» или «Автоответ»), черновик ответа
  крупным блоком с кнопкой «Копировать», затем «Почему так решено»: строка шагов («Язык определён», «Категория», «Найден пункт
  правил», решение), факты, уверенность в ProgressBar, причины списком, время и цена, пометка «Ответ собран по шаблону», если
  модель не вызывалась. Пустое состояние, Alert с «Повторить» при ошибке, свёрнутый `ExpandableSection` «Ответ API (JSON)».
- **Очередь как «список и карточка».** Слева компактный список (срочность словом, название категории, язык, одна строка текста,
  статус), справа всегда открытая карточка (боковая панель `SplitPanel`, на ширине меньше 1000 px панель уходит вниз). Вкладки
  «Ждут (N) / Обработано (N) / Все (N)», поиск, срочность и язык; открыта вкладка «Ждут», первым выбран самый срочный. Критичные
  сверху с красной меткой. В карточке: вердикт, текст игрока, черновик (правится прямо в поле), «Отправить» главной кнопкой,
  «Эскалировать», «Сохранить правку» и «Вернуть исходный текст» появляются при изменении, «Почему так» свёрнуто. После
  «Отправить» или «Эскалировать» выбор сам переходит к следующему обращению, которое ждёт человека; вверху карточки «Осталось: N»
  и подтверждение действия (без сдвига списка). Клавиши `j` и `k` двигают выбор, Ctrl+Enter отправляет ответ.
- **Метрики для не специалиста.** Три вопроса большими числами и одной фразой: «Сколько это стоит и как быстро», «Выдумывает ли
  сервис правила», «Передаёт ли он важное человеку». Числа берутся из чистой проверки (`eval_report_holdout.json`), если она есть,
  иначе из отчёта оценки, цена и скорость при их отсутствии из телеметрии; всегда указан размер выборки. Ниже раздел «Подробно для
  жюри» с техническими названиями, целью, статусом («в норме», «ниже цели», «справочно», «ещё не измерено»), отдельными столбцами
  для данных настройки (in-sample, n=1000) и чистой проверки (holdout, n=300) и пояснением: людской разметки (gold) пока нет,
  сравнение идёт с разметкой модели (silver), это согласие, а не точность.
- `api/metrics.py` (только добавления): в ответ `/api/metrics` добавлены `sample`, `eval` и `holdout` (n, выборка, цена, задержка,
  доля человека и автоответа, число важных обращений без человека, число черновиков с цитатой, число строк gold). Поля строк `rows`
  и их значения не менялись. Чистый отчёт читается из `artifacts/eval_report_holdout.json`. Тест в `tests/test_api_queue.py`.
- Общие части очереди и страницы проверки в `frontend/src/parts.tsx` (`Verdict`, `ProcessSteps`, `TicketFacts`, `CitedRules` с
  поповером, `ReasonList`), названия категорий в `format.ts` (код мелким текстом, `kk` показывается как `kz`).
- Вход: одна карточка и одна строка о продукте. Верхняя панель: название, короткое описание, имя пользователя (меню с «Выйти»),
  кнопка темы. Заголовок вкладки по странице, значок вкладки, подписи полей и кнопок по-русски.
- `VITE_DEMO=1` работает на тех же экранах с теми же фиксированными ответами; в демо метрики «ещё не измерено».

**Проверка.** `make ci` (строка в PR); `pytest tests/test_no_case_text.py` с данными: проходит. Браузер: сервис на 127.0.0.1 с
временными `JURY_PASSWORD` и `SESSION_SECRET`, headless Chrome с Playwright (скрипты во временной папке вне репозитория), 1440x1000
и 1024 по ширине, светлая и тёмная тема: вход, очередь, разбор трёх обращений подряд (отправить, эскалировать, отправить) с
автопереходом и уменьшением «Осталось», клавиши `j` и `k`, страница проверки на ru, uz, kk, платеже, апелляции и пустом
сообщении (живая модель, меньше $0,05 всего), JSON, метрики, сборка демо. Все данные выдуманные.

**Не сделано, риски.**
- Названия категорий лежат в интерфейсе (`format.ts`), а не берутся из `taxonomy.json` на сервере: файла правил на публичном
  инстансе нет. Если таксономия изменится, обновить словарь.
- Причины (`reasons`) приходят с сервера готовым текстом, интерфейс их не переписывает; длинные причины с санкциями показываются как есть.
- В строке шагов нет шага «текст проверен»: сервер не отдаёт результат проверки защиты, показываются только реальные значения.
- Список в очереди показывает 50 обращений на странице; навигация по `j` и `k` идёт в пределах страницы.
- Контраст в тёмной теме проверен по снимкам, автоматического аудита доступности не было.
