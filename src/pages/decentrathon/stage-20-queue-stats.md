**Что просил владелец.** Наверху главного экрана очереди три карточки по макету: «Общая информация», «Приоритеты», «Обработано».
Макет взят как направление. Его недостатки исправлены: подпись доли не лежит поверх кольца, панель невысокая (очередь остаётся
главным делом экрана), срочные приоритеты видны сразу, а ноль не выглядит единицей.

**Откуда числа.** Их считает сервер по ВСЕМ обращениям, не по загруженной странице и не по выбранному фильтру: `GET /api/tickets`
кроме `counts` отдаёт `priority_counts` и `waiting_priority_counts` (`Store.overview()` в `api/store.py`, один запрос группировки по
состоянию и приоритету, поэтому части всегда складываются в целое). Поиск, фильтры, вкладка и номер страницы числа панели не меняют.
После «Отправить», «Эскалировать» и «Сохранить правку» очередь перечитывается, панель обновляется без перезагрузки страницы.

## Что значит каждое число

Состояния обращения (`State`): `human` (нужен человек: ждёт решения администратора), `auto` (автоответ), `duplicate` (дубль),
`sent` (отправлено администратором), `escalated` (передано старшему администратору).

| Где | Число | Определение |
|---|---|---|
| Общая информация | обращений всего | все обращения очереди = сумма всех пяти состояний |
| | ждут решения | состояние `human`; то же число стоит в заголовке «Ждут решения администратора» и во вкладке «Ждут» |
| | Критично / Высокий / P2–P3 | из тех, что ждут решения: сколько с приоритетом p0, p1 и p2+p3; вместе дают «ждут решения» |
| Приоритеты | P0 … P3, второе число в «N из M» | обращения всех состояний с этим приоритетом; четыре M дают «обращений всего» |
| | «N из M» справа от полосы | N обращений ещё ждут решения (`waiting_priority_counts`), M всего с этим приоритетом; закрашенная часть полосы это N, бледная: уже обработаны. Состояние читается из текста, не только из прозрачности |
| Обработано | сегменты кольца и строки легенды | пять состояний, показаны все (в том числе «Отправлено» и «Эскалация», которых нет в макете), вместе дают «обращений всего» |
| | процент в центре | **Обработано, % = (всего − ждут решения) / всего**, целое число |

**Обработано, %.** В числителе всё, что больше не ждёт человека: автоответ, дубль, отправлено, эскалация. Обращения в состоянии
`human` не считаются никогда. Эскалация считается обработанной: администратор принял решение, передал дальше. Это то же число,
что во вкладке «Обработано (N)». Округление до целых, но пока кто-то ждёт, показывается не больше 99%, а как только хоть одно
обращение обработано, не меньше 1% (честные «100%» и «0%» только когда так и есть). При нуле обращений вместо процента тире, деления
на ноль нет.

## Как читается и что учтено

- Полосы приоритетов растут от общей нулевой линии, шкала одна на все четыре. Нулевое значение не рисует полосу (подпись «0» серая),
  ненулевое не уже заметной полоски. P0 и P1 красный и оранжевый, остальное приглушено; строка P0 и P1 подсвечена и жирная,
  только пока такие обращения ещё ждут решения.
- Цвет и прозрачность никогда не единственный признак: у каждой полосы и каждого сегмента есть подпись и число текстом («ждут N из M»).
  Числа настоящие, не картинка; кольцо и полосы скрыты от скринридера, у строки есть скрытый префикс «Ждут решения:», у процента
  «Обработано:». Тире вместо числа несёт скрытый текст «нет данных» (или «обращений нет» при пустой очереди). Карточки это группы, а не
  три отдельные области страницы; `aria-busy` стоит только пока идёт первая загрузка, при ошибке его нет.
- Цвета четырёх состояний прошли `validate_palette.js` из набора dataviz (CVD и обычное зрение, светлая тема); серый «Дубль»
  нейтральный сознательно. Тёмная тема проверена глазами.
- Загрузка и ошибка: те же карточки с тире вместо чисел, высота не скачет, придуманных чисел нет. Ошибка показывается привычным
  Alert с «Повторить».
- Узкая ширина: по ширине самой панели, а не окна. От 600 px три колонки, от 460 до 599 две строки, уже 460 (телефон) полоса
  карточек листается вбок внутри панели, горизонтальной прокрутки страницы нет. Только пока полоса действительно листается, она
  становится областью с подписью и доступна с клавиатуры (`tabIndex`, `ResizeObserver`); на широком экране лишней остановки Tab нет.
- Чтобы на ноутбуке 1366 px три колонки влезли в колонку очереди, боковое меню по умолчанию закрыто на странице очереди (на остальных
  страницах по-прежнему открыто от 1280 px; выбор пользователя запоминается), а карточка обращения справа получила 44% ширины вместо
  48%. Страницы остаются на виду: в верхней панели ссылки на все страницы роли (жюри: Очередь, Проверить обращение, Метрики;
  разработчик: ещё Прогресс, Разметка, Проверка языка; на узком экране они уходят в «Ещё»), текущая подсвечена.
- Итоговая строка в заголовке очереди и отдельный запрос «критичных» убраны: их заменила панель. Фильтры поиска, приоритета и языка
  стоят в одну строку, чтобы строки очереди были видны сразу под панелью.
- Демо (`VITE_DEMO=1`): `data.ts` (`overview`) и `demo.ts` отдают те же поля из демо-обращений; демо живое, после кнопок числа меняются.

## Проверка

- `tests/test_api_queue.py`: пустая очередь (все числа 0, ключи на месте); обращения всех состояний и приоритетов, суммы сходятся
  (состояния = приоритеты = всего, ждущие по приоритетам = `counts.human`); числа не зависят от фильтра, поиска и страницы; после
  `send`, `escalate` меняются, после `edit` нет; обращение, добавленное через `POST /api/tickets` (песочница), прибавляет ровно одно
  к своему состоянию и своему приоритету. `tests/test_roles.py`: гость получает 403 на `/api/tickets` без чисел панели.
- Фронтенда с тестовым запуском в репозитории нет (только сборка с `tsc`), поэтому проверка интерфейса сделана глазами и скриптом
  (Playwright, headless Chromium, скрипты вне репозитория): демо-сборка в 1440x900, 1366x768 и 390x844; светлая и тёмная тема;
  состояния «пусто», «всё обработано», «много обращений», «загрузка», «ошибка» (ответы API подменены); ссылки верхней панели и боковое меню для жюри и разработчика на 1366 и 1440 (подмена `/auth/me`); `j` и `k`, автопереход,
  «Отправить», «Эскалировать», «Сохранить правку» с пересчётом панели; на 1366x768 первые пять строк очереди видны без прокрутки,
  scrollWidth равен ширине окна на всех трёх размерах.
- `make ci`: строка в описании PR.
