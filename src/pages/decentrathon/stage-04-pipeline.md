> Этап 17b добавил режим без модели (`LLM_BACKEND=none`, по умолчанию при отсутствии ключа): вызов модели в `_call_llm`
> заменён ответом `core/offline.py` в том же формате `LLMOutput`, остальные ветки без изменений. Подробности: [17b-local-mode.md](/decentrathon/stage-17b-local-mode/).

**Сделано.**
- `core/pipeline.py`: `async def triage(req) -> (TriageResponse, Telemetry)`, не бросает исключений.
  Порядок: убрать сообщения `admin` → normalize → топ-3 классификатора для своего `kind` → флаги →
  extract → выход без LLM или один вызов LLM → сборка текста по ветке → `guard.check` → приоритет.
  Также `warm()` (правила, контекст, обе модели классификатора).
- `core/telemetry.py`: SQLite (`settings.db_path`, таблица `telemetry`: поля `Telemetry` плюс `ts`, `lang`,
  `category`). `record()` кладёт строку в очередь, пишет фоновый поток; каталог создаётся им же, ошибки
  только в лог, переполнение очереди (10 000) отбрасывает строку.
- `api/main.py`: `POST /triage` (`response_model=TriageResponse`), `GET /health` (наличие артефактов, итог
  прогрева, есть ли ключ LLM, нужен ли `X-API-Key`; секретов нет), прогрев в `lifespan`. При заданном
  `settings.api_key` `/triage` требует заголовок `X-API-Key` (401). Ошибки валидации остаются 422.
  Неожиданная ошибка даёт ответ по контракту (200), не 500.
- `cli/predict.py` и `Makefile`: `make predict IN=… OUT=…` (8 параллельных, прогресс `n/total` в stderr,
  одна строка вывода на строку ввода в том же порядке; плохая строка получает безопасный ответ и код
  `bad_input` в телеметрии). Телеметрия без текста пишется рядом: `<OUT>.telemetry.jsonl`.
  Остальные цели: `install`, `build`, `serve`, `test`, `eval` (заглушка этапа 5).
- `cli/build_context.py`: карта пунктов теперь строится по всем жалобам train (см. ниже).
- `core/draft.py`: в промпт добавлены короткие определения неоднозначных категорий (`CATEGORY_NOTES`),
  параметр `hedge` у `generate`.
- `scripts/ci.sh` и `make ci`: локальная замена Actions (см. `docs/build-plan.md`).
- Тесты: `tests/test_pipeline.py`, `test_api.py`, `test_predict.py`, `test_telemetry.py`, плюс тесты
  псевдометок в `test_context.py`. Общие подделки в `tests/conftest.py`. Сеть и данные не нужны.

**Ветки конвейера.**
0. Сообщения `admin` отбрасываются первыми; текст каждого сообщения режется до 4 000 знаков, сообщений
   не больше 40 (регулярки `_NICK` в `kbprep` и `context` были квадратичными: 50 000 знаков держали цикл
   событий 5 с, теперь они линейны и вход ограничен).
1. Пусто или только токены (`<url>`, `<digits>`, меньше 3 букв): ответ `fast_reply`, без LLM, путь `fast`.
   Категория по умолчанию `report.offtopic` / `complaint.invalid`, `needs_human=false`. Если текст не пуст
   и классификатор уверенно (≥0,65) видит другую категорию своего вида (голая ссылка, «дм»), категория
   остаётся его, `needs_human=true`.
2. Флаг апелляции у жалобы → `complaint.admin` всегда, даже вне топ-3. Флаг платежа или аккаунта у
   репорта → `report.payment` / `report.account` всегда, даже вне топ-2 (оба флага: выше по
   классификатору, при равенстве платёж). Во всех трёх: `safe_reply`, без LLM, `needs_human=true`, путь `fast`.
3. Иначе `build_context` по топ-2 и один вызов LLM внутри `total_budget_s`. Категория:
   жалоба: классификатор, если его top-1 ≥ `CLASSIFIER_TRUST` (0,65), иначе модель из топ-3 (вне топ-3
   берётся top-1); репорт: всегда модель (вне топ-3 берётся top-1).
   - Жалоба по существу (insult, cheat, dm, scam, rmt_ads, other): `render_complaint` в режиме
     `settings.draft_mode`; пункт из `cited` модели, при пустом или негодном `cited` это `primary_ref`
     категории (источник `template`); в тексте один пункт, в ответе `cited` не больше 2. Пункты ЖБ как
     нарушенное правило не цитируются. Санкция для ru берётся целыми вариантами до 150 знаков
     (`_player_sanction`), для uz и kk шаблон сам разбирает первую часть (см. ниже). В режиме `neutral`
     `reasons` содержит подсказку санкции для админа. `needs_human=true`.
   - `complaint.invalid`: `invalid_reply` с пунктом ЖБ. `needs_human=false` только при строгом правиле
     (`_clear_format_defect`): top-1 классификатора это `complaint.invalid`, уверенность модели ≥0,8,
     нет флага апелляции или угрозы, нет доказательств, в тексте не больше 4 слов. Иначе человек.
   - `report.question`: текст модели, только если есть попадание в базу знаний, иначе `safe_reply` и
     `needs_human=true`. `report.help`, `report.complaint`: текст модели, если проходит проверку, иначе
     `safe_reply`, человек нужен. `report.account`, `report.payment`, `complaint.admin`: всегда `safe_reply`.
     `report.offtopic`: `fast_reply`.
4. `needs_human=true` всегда для `NEEDS_HUMAN_ALWAYS`, при угрозе (regex-флаг или LLM), уверенности <0,6 и
   любой ошибке проверки. Приоритет: `priority_for` с `threat_irl` и `large_property` от модели.
5. Ошибка проверки: `safe_reply`, категория сохраняется, в `reasons` причина, коды в `Telemetry.guard_failures`.
   Если упала только цитата (`quote_*`), пункт заменяется на `primary_ref`.
6. Любое исключение: ответ по классификатору с `safe_reply`, `path="fallback"`. Если сломан и классификатор,
   `_emergency` всё равно собирает валидный ответ по шагам.

`Telemetry.path`: `fast` (LLM не нужен), `llm` (модель ответила; при ошибке проверки путь тот же, коды в
`guard_failures`), `fallback` (модель недоступна, бюджет вышел или внутренняя ошибка). Поле `Telemetry.error`
(и столбец `error` в SQLite) хранит причину: статус провайдера, `budget_timeout_in_queue`,
`budget_timeout_in_call`, `internal:<тип>`.

**Всплески нагрузки.** 50 одновременных запросов давали массовый запасной ответ. Причина найдена
замерами: не 429 (ни одного) и не локальные затраты (2,5 мс на тикет), а повторный запрос (hedging) через
2 с. Под нагрузкой каждый медленный вызов удваивается, провайдер замедляется ещё сильнее. При 50
одновременных и hedging 2 с в бюджет уложились 16 из 50 (при пределе параллелизма 25: 33 из 50), с отключённым hedging все 50
(медиана вызова 1,5 с). Исправление: (1) процессный предел параллельных вызовов модели
(`LLM_CONCURRENCY`, по умолчанию 24, семафор на цикл событий; очередь ждёт внутри бюджета, исход
`budget_timeout_in_queue` в телеметрии); (2) hedging выключается, когда в работе больше
`HEDGE_MAX_INFLIGHT` (4) вызовов (`draft.generate(..., hedge=False)`). Контрольные всплески с живой
моделью: 50 одновременных, все 50 ответов моделью (макс. 4,3 с, второй раунд 3,7 с), 30 одновременных: все 30 (макс. 3,5 с).
Бюджет 4,5 с при 50 одновременных выдерживается впритык: при большем потоке нужен предел снаружи.

**Санкции на uz и kk.** `templates.sanction_for_lang` теперь разбирает структуру (вид наказания, диапазон
«от X до Y», «до Y», «на X», «навсегда», единицы, префикс «Грубое нарушение», несколько наказаний через
«+»), берёт первую часть и пример-подпись («Примечание», «Уточнение») отбрасывает: `mut 15 daqiqadan 30
daqiqagacha`, `мут 15 минуттан 30 минутқа дейін`. Разобралось 156 из 204 санкций правил (76,5%; 156 из 188
тех, где есть слово наказания, 83%). Не разобралось: исключения, «всем участникам», составные меры лидерам,
«согласно правилам». Слова и падежные окончания написаны без носителя, нужна проверка носителем.
В живой выборке 200 тикетов санкция показана в ответах по существу: ru 67 из 75, uz 12 из 15 (было 0 из 15), kk
в выборке один тикет.

**Качество категории.** Прошлые цифры (итог 0,61 против 0,70 у классификатора) относились к выборке с
перекосом в uz и kk и к варианту, где категорию всегда выбирала модель; они заменены цифрами выше. На
220 случайных тикетах ревью дало 0,645 против 0,791. Причина: модель выбирала `complaint.invalid` для
коротких жалоб без нарушителя и доказательств, которые серебро и классификатор называют по теме.
Теперь жалобу решает уверенный классификатор, репорт модель. Разбор расхождений на 200 тикетах:
ниже порога модель выигрывает у классификатора 13 против 9, быстрый путь до правки проигрывал 6 против 1
(ссылка или «дм» без букв), флаг апелляции 1 против 0. Серебро делалось по запросу игрока и расходится
с буквальным чтением таксономии («без доказательств»); золотая выборка может сдвинуть значения.

**Не сделано, риски.**
- Золотой выборки нет, поэтому категория и `needs_human` проверены только на согласие с серебром.
- Классификатор получает только текст игрока без региона (`predict_topk` его не принимает), а обучался
  с регионом: небольшое расхождение признаков.
- Определение `has_evidence` требует ссылку или вложения вместе со словами; «скриншот есть» без вложений
  доказательством не считается, отсюда p3 у части жалоб (решение этапа 2).
- `is_spam_or_duplicate` всегда false (этап 7).
- Тексты uz и kk шаблонов, слова и падежи санкции не проверены носителем. 24% санкций правил не
  разбираются (исключения, составные меры лидерам): тогда ответ нейтральный.
- На 50 одновременных запросах бюджет выдерживается впритык (макс. 4,3 с); при большем потоке нужен
  внешний предел или горизонтальное масштабирование.
- `make ci` проверяет только закоммитированное; GitHub Actions в репозитории не запускается.
- Пересобранные `category_rules.json` и `style_notes.md` лежат в общем `ARTIFACTS_DIR`; `make build`
  переобучает классификатор из серебра, поэтому здесь запускался только `build_context`.
- Телеметрия SQLite растёт без ротации.

**Важно дальше.** Этап 5 берёт `python -m cli.predict` и `<OUT>.telemetry.jsonl`; сравнивать режимы
(`DRAFT_MODE`), модели и `CLASSIFIER_TRUST` по золоту. Этап 6 вызывает `pipeline.triage` напрямую и
пишет через `telemetry.record`. Рабочие файлы живых прогонов лежат только в `runs/` (в git не попадают).


## Контрольный замер оркестратора

Финальный код, новая случайная выборка из 200 тикетов valid, полный прогон без склейки: согласие с
серебряной разметкой 0,775 (жалобы 0,734, репорты 0,913), у классификатора 0,721 и 0,848. p50 1,01 с,
p95 1,65 с, средняя цена $0,00046, максимальная $0,0015, выдуманных цитат 0 из 94, откатов проверки 1.

Этот замер выявил остаток блокера: 28 жалоб были отклонены автоматически, из них 8 серебряная
разметка считает настоящими, 3 из них апелляции. Короткий текст не признак дефекта: админы одобряют
короткие жалобы, если доказательство во вложении, а его сервис не видит. Поэтому жалоба с вложением
или ссылкой теперь всегда идёт человеку. В выгрузке вложение есть у всех жалоб, так что
автоотклонение остаётся только для запросов без вложений.

### Правки второго ревью

- Одно условие `_has_proof(base)` (жалоба с вложением или ссылкой) используется на всех путях, где
  жалоба могла остаться без человека: быстрый путь, `_clear_format_defect`, `_invalid`. При наличии
  доказательства текст всегда `safe_reply` (не «исправьте оформление»), `needs_human=true`; быстрый путь
  теперь тоже учитывает вложения (раньше пустой текст с `images_count=1` отклонялся).
- Ссылки: `classify.has_link` ищет литерал `<url>`, любую схему, `www.` и «домен/путь»
  (`t.me/x`, `vk.com/id1`, `discord.gg/abc`), а голый домен без пути только с частыми зонами; «2.1»,
  «ok.then», точки в предложениях ссылками не считаются. Ссылки в тексте учитываются и в `extract`.
- `TriageRequest.attachments()` = max(`images_count`, сумма по сообщениям всех ролей кроме admin),
  включая `reported_player`.
- Санкция: при «или» и «/» выводятся обе альтернативы, если обе разобраны (`yoki` / `немесе`).
  Если что-то отброшено (вторая часть после «;», неразобранная альтернатива, длинный вариант на ru),
  полный текст санкции остаётся в `reasons`. Для uz латинские слова пропускаются только если они из
  словаря шаблона: `SPAWN` и подобное отбрасываются.
